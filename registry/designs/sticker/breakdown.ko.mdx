# 스티커 — 제작기

## 훅: 만지는 웹사이트

서울 마포구의 2인 디자인 스튜디오가 자기 웹사이트 전체를 스티커로
지었다. 스티커 *그래픽*이 아니라 진짜로 끌고 던질 수 있는, 쫀득하게
튀어오르는 스티커. 워드마크가 스티커고, 섹션 번호가 스티커고, 괜찮아
도장도, 비밀 태그도, 별 다섯 개도, 책상에 테이프로 붙은 손글씨 메모도,
커피잔도, 쪽지 화살표도, 뿅! 효과음도 — 전부 스티커, 전부 잡을 수 있고,
전부 던질 수 있다. 이 페이지는 "만지고 싶어서 왔겠지, 남은 건 뭘 먼저
잡을까뿐"이라는 태도로 시작한다.

디자인의 도박은 하나다. 물리가 진짜여야 장난이 공예로 읽힌다는 것.
스티커가 두 번 통통 튀며 제자리로 돌아올 때, 그 장난은 정당해진다.
그냥 translate로 돌아오는 스티커는 색칠한 상자일 뿐이다. 그래서 이
페이지는 스프링을 한 번, 그리고 전면에 건다. 놓기도, 키보드로 밀기도,
버튼 누르기도 — 전부 같은 적분기를 지난다.

## 아트 디렉션

팔레트는 곧 스티커팩이다. 따뜻한 흰색 바탕(`#fef8ee` — 책상), 잉크 하나
(`#1a1a1a` — 통통한 외곽선이자 모든 기능 글자), 그리고 포화된 스티커
여섯 개 — 귤, 하늘, 라임, 포도, 레몬, 버블. 이 팔레트를 하나로 묶는
규칙은 스타일이 아니라 접근성이다. 잉크 글자가 *모든* 포화 색 위에서
AA를 통과한다(5.0:1–12.6:1). 통통한 검정 외곽선과 라벨 글자가 같은 색으로
같은 일을 하는 이유다. 흰색 글자는 전부 실패한다(포도 위가 최고 3.48:1)
그래서 디스플레이 전용이다. 브랜드 액센트인 귤빛은 바탕 위에서 2.5:1이라
기능 글자나 포커스 링으로는 쓰지 않는다 — 더 깊은 `#bf421a`(4.96:1)가 그
역할을 한다. 귤빛은 스티커 채움, 워드마크 바탕, 그리고 잉크 푸터 위의
링 색으로만 산다.

서체 셋은 각자 직업이 있고, 한국어가 먼저다. 블랙 한 산스는 시끄러운
표지 목소리(워드마크 스티커, 섹션 제목, 스티커의 큰 한글 라벨)를 맡고,
개구체는 노트 필기체(캡션, 테이프 붙인 메모, 보조 라벨 — 시스템 글꼴이
아니라 볼펜으로 쓴 느낌)를 맡고, 프레도카는 영어 목소리(부제목, 마퀴
영어, 장부손)를 맡는다. 로마자 스택은 모두 한국어 서체를 먼저 나열하고
`:lang(ko)` 규칙이 고정하므로, 한글은 절대 기본 sans로 빠지지 않는다.
한국어가 이 페이지의 첫 목소리라는 걸 타이포 시스템 자체가 증명한다.

## 기법 1 — 드래그 물리: 통통 튀는 스티커 작업대

시그니처 섹션은 둥근 모서리 책상 위에 스티커 열한 장이 흩어져 있는
작업대다. 전부 CSS와 인라인 SVG, 이미지는 한 장도 없다. 잡아서 던질 수
있다. 물리는 손으로 말았고, 게다가 — 블런트의 사촌과 달리 — 마찰 활주
와 벽이 아니라 **진짜 스프링**이다.

각 스티커는 점 질량 하나로, `dx, dy`(CSS로 흩어 놓은 기본 위치에서의
델타라 JS가 꺼져도 똑같이 흩어져 있다 — 그냥 가만히), `vx, vy`, 그리고
지어낸 회전을 갖는다. 놓는 순간 제자리 `(0,0)`로 향하는 언더댐핑
스프링이 당기는데, **정규화 프레임 공간**에서 준묵시적 오일러로 적분한다:

```ts
// useStickerPhysics.ts — 속도는 raw-dt가 아니라 프레임 단위 공간에 산다.
// 그래서 스프링이 무조건 안정적이다. 밀린 스티커는 프레임레이트와
// 상관없이 ~590ms에 두 번 튀며 가라앉는다.
const fr = dt / 16.7;
b.vx += -SPRING_K * (b.dx - b.homeX) * fr;   // k = 0.18
b.vy += -SPRING_K * (b.dy - b.homeY) * fr;
const damp = Math.pow(1 - SPRING_C, fr);      // c = 0.40, 언더댐핑
b.vx *= damp;
b.vy *= damp;
b.dx += b.vx * dt;
b.dy += b.vy * dt;
```

상수는 코드로 옮기기 전에 시뮬레이션으로 돌려 뽑았다. `k=0.18, c=0.40`이
변위·던지기·강한 던지기 전 시나리오에서 2–3번 튀며 420–600ms에 가라앉는
최적점이었다. 더 세면 너무 빨랐고, 더 무르면 끌렸다. 놓는 순간의 초기
속도는 마찰 0.92로 먼저 빠진 뒤 스프링에 넘겨진다 — 사실 스프링은 항상
켜져 있어서 그냥 운동량을 흡수할 뿐이고, 그래서 세게 던져도 책상 밖으로
날아가지 않고 제자리로 돌아온다.

상수보다 중요한 구조적 결정이 둘 있다. 첫째, 물리 상태는 CSS 기본 위치
에서의 델타라, 흩어진 배치(left/top 퍼센트와 스티커별 `--sticker-rot`
커스텀 프로퍼티)는 전부 스타일시트에 있다 — JS는 오직 `style.transform`만
쓴다. 둘째, React는 껍데기를 딱 한 번 렌더링하고 그 뒤는 전부 명령형이다.
풀 스윙 던지기에도 리렌더 0회.

쌓임은 블런트가 하지 못했던 부분이다. 놓인 스티커는 반경 합의 1.1배
안에 있는 쉬고 있는 이웃과 부드럽게 충돌해, 겹침의 0.35만큼 밀어내고
운동량의 한 조각을 넘겨준다:

```ts
// 움직이는 스티커가 쉬고 있는 이웃을 반경 밖으로 민다 — 둘 다 이후
// 스프링으로 제자리 간다. 쌓임처럼 보이지만, 정직한 충돌 해석기는 아니다.
const overlap = min - dist;
other.dx += nx * overlap * PILE_SHOVE;
other.dy += ny * overlap * PILE_SHOVE;
```

스티커를 다른 스티커 위에 떨어뜨리면 둘이 부대낀 뒤 스프링이 둘 다
끌어당기고, 실제 스티커 두 장이 맞닿은 것 같은 작은 겹침이 남는다.
운동량 보존도 없고 정지 접촉 해석기도 없다 — 효과는 친절함이지 물리법칙이
아니며, PROMPT.md에 그렇게 적혀 있다.

토크는 블런트의 작업대와 같은 정직한 거짓말이다 — 놓는 속도와 잡은 지점의
외적(`vr += 0.5 × (vx·−gy + vy·gx)`). 모서리를 잡고 홱 당기면 돌고,
정중앙을 잡으면 안 돈다. 세 줄이 손맛의 90%를 만든다. 놓는 속도는
2.2 px/ms로 제한돼 가장 센 던지기도 책상 안에서 튀어 돌아온다. 잡고 있던
스티커는 놓는 순간 시계를 본다 — 90ms 넘게 움직임이 없었으면 속도를
0으로 한다. 그건 던진 게 아니라 *놓아둔* 것이다. 모션 최소화에서는 모든
놓기가 놓아두기가 되고 제자리로 스냅한다.

## 기법 2 — 포인터 패럴랙스: 깊이가 있는 무더기

히어로는 미니 스티커 작업대다. 워드마크가 한가운데 떠 있고, 그 주변에
작은 스티커 무더기(초록 READY, 파란 별, 분홍 하트, 귤빛 뿅!)가 세
깊이로 앉아 있다. 포인터를 움직이면 층마다 다른 속도로 흔들린다 — 먼
층은 거의 안 움직이고, 가까운 층은 바짝 따라온다. 흔들림은 ±18px로
제한되고 지수 lerp로 부드럽게 따라가므로 포인터를 뒤따른다 — 이게
핵심이다. 패럴랙스가 깊이로 읽히려면 뒤처져야 한다.

```ts
// usePointerParallax.ts — 층이 목표를 부드럽게 뒤따른다.
const k = 1 - Math.pow(0.82, dt / 16.7);
curX += (targetX - curX) * k;
for (const l of layers) {
  l.el.style.transform = `translate3d(${(curX * l.depth).toFixed(2)}px, …)`;
}
```

각 층은 `data-sticker-parallax="0.04"`(먼 고스트 외곽선)부터 `0.20`(앞쪽
데칼)까지의 값을 갖는다. 훅은 이들을 한 번 쿼리해서 먼 층부터 정렬해
가까운 층이 위에 칠해지게 하고, rAF 루프는 층들이 목표에 안착하면
스스로 멈춘다 — 포인터가 쉬면 0프레임. `pointerout`이 목표를 0으로
돌려 포인터가 나가면 무더기가 제자리로 가라앉는다. 모션 최소화에서는
훅이 아예 붙지 않고, 무더기는 CSS 기본 위치에 가만히 있다.

히어로의 데칼들은 `.sticker-sticker` 물체이기도 해서, 작업대를 쥐고 있던
같은 `useStickerPhysics` 엔진이 이것들까지 쥔다 — 히어로가 분리된 물리
섬이 아니다. (워드마크 자체는 `pointer-events: none`이다 — 떠 있다.
드래그 가능하게 만들면 조상의 패럴랙스 transform과 충돌해 잡힐 때
튀었기에, 배경으로 남겨뒀다 — PROMPT.md 참고.)

## 기법 3 — 스크롤을 읽는 마퀴

서비스 티커 두 줄이 서로 반대 방향으로 달린다. A줄은 분야(브랜딩,
웹사이트, 웹툰, 일러스트, 모션)를 하늘색 위에, B줄은 형용사(재밌게,
끈적하게, 통통 튀게, 기억에 남게, 색깔 있게)를 귤빛 위에. 페이지의
스크롤 방향이 둘을 뒤집는다 — 아래로 스크롤하면 A는 왼쪽, B는 오른쪽,
위로 스크롤하면 반대. 스크롤 속도는 티커 속도에 먹인다. 반전이 무게감으로
읽히는 건 부호 있는 속도가 지수 lerp로 목표를 쫓기 때문이다:

```ts
// ServiceMarquee.tsx — 반전은 순간이동이 아니라 미끄러짐이다.
const k = 1 - Math.pow(0.86, dt / 16.7);
curA += (e.dir * -speed - curA) * k;   // 두 줄은 반대 부호를 쫓는다
offA = wrap(offA + curA * dt, wA);
```

스크롤을 뒤집으면 `curA`는 반대 방향을 얻기 전에 반드시 0을 통과해야
한다. 그래서 줄이 눈에 보이게 제동을 걸고, 한 박자 멈췄다가, 반대로
미끄러진다. 그 감속이 이 밴드의 성격이다. 배관은 블런트와 같다. 각 줄은
동일한 단어 그룹 네 벌을 들고 있고, 오프셋은 그룹 하나의 실측 너비에서
순환하며(`ResizeObserver`가 실측을 갱신), 밴드 전체는
`IntersectionObserver`가 화면에 있다고 할 때만 프레임을 쓴다. 스크롤
상태는 패시브 리스너가 쓰는 가변 ref에 산다 — React 상태도, 리렌더도
없다. 움직이는 줄은 `aria-hidden`이고, 모든 단어는 그 앞의 시각적으로
숨긴 문단에서 정확히 한 번씩 전달된다.

## 보조 모션 — 프레스, 리빌, 흔들림

프레스는 스프링의 아우성 같은 동생이다. 스티커는 `:active`에서 0.94로
찌그러졌다가 90ms 들어가 / 120ms 나오며 이즈-백 곡선
(`cubic-bezier(0.34, 1.56, 0.64, 1)`)으로 튀어 오른다 — 살짝 오버슈트,
엄지에 찌그러진 스티커. 버튼은 4px 밀리며 그림자가 접힌다. 이것은
선언된 세 기법 중 하나가 아니다. 스프링이 기능이 아니라 페이지의
재질로 느껴지게 만드는 결합 조직이다.

리빌은 `.sticker-js` 아래에서 섹션을 `opacity 0 / translateY(24px)`로
숨겼다가(JS가 꺼져 있으면 바로 보이게) `IntersectionObserver`에서
`.is-revealed`를 준다. 700ms 이즈-백, 90ms 지그재그 — 떼어 올리는
스티커. 모션 최소화에서는 아무것도 숨기지 않고 아무것도 트랜지션하지
않는다.

## 모션 수학

- **스프링 k=0.18, c=0.40.** 300px 변위가 ~590ms에 두 번 튀며 가라앉고,
  던지기(v0≈1.8)는 ~420ms. 정규화 프레임 공간의 준묵시적 오일러는 이
  값에서 무조건 안정적이라, 느린 프레임(dt 48ms 제한)이 와도 스프링이
  터지지 않는다.
- **던지기 마찰 0.92.** 초기 운동량이 정규화 프레임당 ~8% 빠진 뒤
  스프링이 흡수한다 — 던짐이 돌아오기 전에 이동할 만큼, 도망갈 만큼은
  아니게.
- **토크 `0.5 × (vx·−gy + vy·gx)`.** 모서리(gx≈±0.5)를 잡고 자신 있게
  끌면 스티커가 ~30°/s로 돌고, 중앙을 잡으면 안 돈다. 세 줄이 손맛의
  대부분.
- **쌓임 밀기 0.35.** 떨어뜨린 스티커가 겹침의 3분의 1을 이웃에
  넘기고, 둘 다 스프링으로 제자리 간다. 접촉 해석기 없이도 쌓임이
  사실처럼 겹친다.
- **패럴랙스 `1−0.82^(dt/16.7)`.** 포인터 오차의 반감기 ~3.5프레임
  (~58ms) — 부드럽고 눈에 띄는 뒤따름.
- **마퀴 접근 `1−0.86^(dt/16.7)`.** 반감기 ~4.5프레임(~75ms) — 미끄러짐이
  보이되 느리지 않다.

## 성능 노트

- rAF 루프는 셋(스티커 물리, 패럴랙스, 마퀴)이고 전부 스스로 꺼진다.
  물리 루프는 모든 물체가 잠들면(0.004 px/ms 미만) 멈추고, 패럴랙스는
  층이 목표에 안착하면 멈추고, 마퀴는 `IntersectionObserver`로 화면 밖에서
  멈춘다. 셋 다 `visibilitychange`에서도 멈춘다. 가만히 있는 페이지 =
  0프레임.
- 움직이는 건 전부 `transform`(더하기 잡기/프레스의 box-shadow 상태
  교체). 레이아웃/페인트 속성은 아무것도 움직이지 않는다. 그레인과
  점 격자는 한 번 래스터되는 정적 그라디언트/필터다.
- 드래그는 캡처된 포인터 이벤트에서 `style.transform`을 직접 쓴다 —
  핫 패스에 React 상태가 없고, 풀 스윙 던지기에도 리렌더 0회.
- `dt`는 어디서나 48ms로 제한되고 스프링은 정규화 프레임 공간에서
  적분되어, 백그라운드 탭이 깨어나도 스티커가 순간이동하거나 스프링이
  터지지 않는다.
- 캔버스 없음, 이미지 없음, 의존성 없음. 가장 무거운 에셋이 구글 폰트
  세 종이다.

## 접근성 노트

- **모션 최소화:** `usePrefersReducedMotion`이 티커를 세우고, 스티커
  놓기를 제자리 스냅으로 바꾸고, 패럴랙스를 떼고, CSS 블록이 리빌 숨김을
  풀어 아무것도 안 보이는 채로 남지 않게 한다. 페이지가 잃는 것은
  통통 튈 뿐이다.
- **No-JS:** 스티커 흩어 놓기는 CSS고, 티커는 읽을 수 있는 서비스 띠이며,
  `.sticker-js`가 그랩 커서와 리빌 숨김을 게이트한다. JS 없는 페이지는
  완성된 스티커 무더기다.
- **키보드:** 모든 스티커는 포커스 가능한 `role="button"`에 "draggable
  sticker" `aria-roledescription`을 달았다 — 방향키로 10px씩 밀면(스프링이
  제자리로 당김), 엔터/스페이스로 맨 위에 올리고, 공용 힌트 요소를
  `aria-describedby`로 참조한다. 포커스는 3px 잉크 링(16.5:1 — 모든
  표면에서 3:1 UI 임계를 넘는 유일한 링)이고, 잉크 푸터 위에서는 귤빛.
- **대비:** 모든 포화 스티커 위 잉크가 AA를 넘는다(5.0:1–12.6:1). 잉크/바탕
  16.5:1, 딥 귤/바탕 4.96:1. 포화색 위 흰색과 바탕 위 귤빛은 디스플레이
  전용이며 그렇게 문서화돼 있다.
- **한국어 우선 이중언어:** 모든 스티커 라벨, 워드마크, 섹션 제목, 푸터
  외침이 한국어로 시작하고 영어가 뒤따른다. 마퀴의 움직이는 줄은
  `aria-hidden`이고, 모든 서비스 단어는 그 앞의 시각적으로 숨긴 문단에서
  한 번씩 전달된다.

## 리믹스 아이디어

1. **스티커팩 포트폴리오.** 스프링은 그대로 두고 스튜디오 스티커를
   프로젝트 카드(브랜딩, 웹사이트, 웹툰처럼 한국어 먼저인 제목의
   드래그 가능한 스티커)로 바꾼다. 방문객이 당신 작업을 물리적으로
   재배열하게 둔다. 쌓임이 기능이 된다 — 프로젝트 세 개를 같이
   떨어뜨리면 뭉친다.
2. **카페 메뉴 벽.** 작업대가 음료 스티커 메뉴(아메리카노, 라떼,
   레몬에이드)가 되어 내가 고른 걸 '주문함' 트레이로 끌어 넣게 한다.
   확정하지 않은 건 스프링이 벽으로 되돌린다. 안녕! 말풍선이 오늘의
   추천이 된다.
3. **아이 한글 학습 게임.** 같은 물리에 한글 음절 스티커(가, 나, 다)를
   달아 아이가 단어 칸으로 끌게 한다. 쌓임이 틀린 답을 정중하게 모아주고
   스프링이 되돌린다. 정답을 쌓으면 뿅! 효과음이 터진다.
