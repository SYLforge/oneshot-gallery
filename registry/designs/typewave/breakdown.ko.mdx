# TYPEWAVE — 해설

## 갈무리

악기를 전부 거절하고 타이포그래피만 남긴 전자음악 아티스트가 한 명 있다.
그의 발매물에는 BPM과 재생시간과 라이너 노트가 있고, 트랙리스트와 엔드
크레딧이 있다. 없는 것은 오디오와 비디오, 그리고 단 한 장의 이미지다.
"파형"은 늘어나는 글자 한 자이고, "타임라인"은 가변 폰트의 축이 스크럽되는
것이고, "티커"는 가사가 흐르는 마퀴 띠다. 이 페이지는 그 전제를 문자 그대로
받아들인다 — 당신이 보는 모든 비주얼라이저가 움직이는 타이포그래피이며,
그 외에는 아무것도 없다.

디자인의 베팅은 이것이다: 키네틱 타이포그래피가 온전한 음악 비주얼라이저가
될 수 있다. 타입이 곧 스펙트럼 분석기이자 재생 머리이자 가사 롤인 페이지 —
미디어 페이로드는 전혀 없이 — 가 히어로 비디오보다 더 리드미컬하게 느껴질
수 있다. 왜냐하면 그 리듬은 당신이 스크롤로 직접 모는 것이기 때문이다.

## 아트 디렉션

여기서 키네틱 타이포그래피란, 타입만이 빛을 받는 표면이라는 뜻이다. 바탕은
완전한 `#000` — 조명이 꺼진 무지 — 이고 그 위에는 타입만 있다: 목소리를
실은 잉크 `#fafafa`(20.1:1, AAA), 기계 메타데이터를 위한 잉크-딤 `#98948a`
(6.9:1, AA+), 그리고 산성 액센트 `#c6ff3a` 단 하나(검정 위 17.8:1). 산성은
색채 구성이 아니라 *사건*으로 다룬다 — 포커스 링, 선택 영역, 스크럽
재생머리, 반전된 마퀴 띠, 섹션 헤드 번호, 희미한 스펙트럼 실선. 뷰포트당
산성이 등장하는 횟수를 세어 보면 적어야 한다. 두 번째 색도, 그라디언트도,
그레인도 없다 — 그 어느 것을 넣는 순간 "타입이 악기"라는 전제가 옅어진다.

네 서체가 네 역할을 맡는다. Archivo는 신디사이저다 — 폭 축(wdth 62–125)과
굵기 축(wght 100–900)을 함께 불러오는 가변 폰트이며, 폭 축이 곧 이 페이지
전체의 키네틱 전부다. Black Han Sans는 한국어 드럼 — 묵직하고 네모난, 워드
마크가 번역되어 들어가는 질량. Noto Sans KR은 한국어 본문 목소리. Space
Mono는 패치 시트 — BPM, 타임코드, 트랙 번호, 축 읽기값. 디스플레이 스택
(`Archivo, Black Han Sans, sans`)은 디스플레이 헤드 안의 한글 글리프가
Archivo를 뚫고 Black Han Sans로 떨어지게 한다 — 기본 산 세리프가 아니라
의도된 무거운 서체로. 그리고 `:lang(ko)`가 한국어를 자기 서체에 고정하며
`word-break: keep-all`을 건다.

## 기법 1 — 글자 분할 리빌, 반응형으로

전통적인 글자 분할은 부모에 `aria-label`을, 글리프마다 `aria-hidden` 스팬을
얹고 스태거로 밀어 넣는다. TYPEWAVE는 그 문법을 그대로 두고 층을 하나 더
얹는다: 글리프가 *반응*한다. 히어로 워드마크 TYPEWAVE가 글리프 단위로
떠오른 뒤(45ms 스태거, 640ms 상승) — 정밀 포인터, 저모션 아닐 때 — 페이지의
스크롤 속도가 각 글리프의 `scaleX`를 쓴다. 스크린 리더는 여전히 "TYPEWAVE"
를 한 번 읽고, 시력이 있는 방문객은 스크롤에 맞춰 글자가 파형처럼 늘어나는
걸 본다.

속도는 공유 ref 하나에서 나온다. 작은 훅이 먹인다:

```ts
// useScrollVelocity.ts — 진폭 버스
const onScroll = () => {
  raw = Math.min(Math.abs(dy / dt) / maxOut, 1.6); // |v| in px/ms, 정규화
  if (!raf) raf = requestAnimationFrame(tick);
};
const tick = () => {
  ref.current += (target - ref.current) * 0.14 * k; // 샘플로 접근
  raw *= 0.86;                                        // 샘플 자체가 식는다
  if (ref.current > 0.001 || raw > 0.001) raf = requestAnimationFrame(tick);
};
```

결정적으로 `ref`는 state가 아니라 `useRef`다 — 그래서 히어로와 트랙리스트
헤드가 자기 rAF 루프 안에서 매 프레임 `velRef.current`를 읽어도 React 재렌더
하나 일으키지 않는다. 히어로 루프는 그 값을 글리프마다 transform 하나로
쓰며, 위상을 교대로 걸어 늘어남이 균일한 부풀음이 아니라 파도로 읽히게 한다:

```ts
// Hero.tsx — 진폭을 글리프에 쓰기
const amp = shown * VEL_GAIN; // 최대 0.42 추가 늘어남
for (let i = 0; i < glyphs.length; i++) {
  const phase = (i % 2 === 0 ? 1 : -0.7) * amp;
  glyphs[i].style.transform = `scaleX(${(1 + phase).toFixed(4)})`;
}
```

분할 자체는 접근성을 지킨다: `<h1>`이 `aria-label="TYPEWAVE"`를 들고, 시각용
스팬은 `aria-hidden`이며, 등장 애니메이션의 `animation-fill-mode: backwards`
는 *오직* `.typewave-js` 아래에서만 작동한다 — 자바스크립트가 없으면 글리프
는 100% 키프레임(완전히 보이는 상태)에 앉아 있고 아무것도 가려지지 않는다.
저모션에서는 속도 훅이 arm되지 않고 글리프는 `scaleX(1)`에서 쉰다.

마무리 워드마크 "PLAY IT AGAIN"은 똑같은 글자 분할 어휘를 재사용해서, 페이지
가 같은 제스처로 열리고 닫힌다 — 다만 모프의 종착 상태(wdth 125, wght 900)
에 머무르며 등장만 애니메이션한다. 페이지는 반복이 아니라 잡고 해결된 화음
위에서 끝난다.

## 기법 2 — 스크롤 스크럽 핀: 축을 타임라인으로

시그니처는 320vh 통로가 100svh 무대를 고정(pin)하는 것이다. 스크롤 진행도가
워드마크 TYPEWAVE를 Archivo의 축 전체 범위에 매핑한다 — `font-variation-
settings`가 통로가 0 → 1로 스크럽됨에 따라 `'wdth' 62 → 125`, `'wght' 100 →
900`으로 보간된다. 이것이 곧 오디오 타임라인이다: 워드마크가 머리에서 얇고
좁게 열려, 본문을 지나며 채워지고 넓게 늘어났다가, 꼬리에서 가장 넓고 무겁게
꽂힌다 — 스펙트럼을 쓸고 지나가는 필터처럼.

```ts
// ScrubWordmark.tsx — 스크롤 진행도가 모프의 유일한 시계
const ease = (t) => t * t * (3 - 2 * t); // smoothstep
const apply = (p) => {
  const e = ease(p);
  const wdth = lerp(62, 125, e);
  const wght = lerp(100, 900, e);
  word.style.fontVariationSettings = `'wdth' ${wdth}, 'wght' ${wght}`;
};
// rAF 루프 안에서 보이는 위치는 질량처럼 타겟을 뒤쫓는다
currentP += (targetPRef.current - currentP) * 0.14 * k;
```

smoothstep이 중요하다: 모프의 *중간*이 가장 빠르게 지나가게 만들어, 워드마크
가 양 극단(얇음/좁음과 넓음/무거움)에 가장 오래 머물고 중간에 가장 짧게
머문다 — 필터 스윕이 느껴지는 그대로. 선형 이징은 반대로 모프를 스톱워치
처럼 만들었을 것이다.

Space Mono HUD가 무대 위에 앉는다 — `wdth 84`, `wght 340`, `0 → 1 · scrub`
— 값이 바뀔 때만 명령형으로 ref에 써서, 읽기값이 패치 시트처럼 틱틱거리게
하고 React를 재렌더하지 않는다. 2px 산성 재생머리가 2.4s `ease-in-out
alternate` 투명도 맥동(깜빡임이 아니라 잡고 있는 비트)으로 위치를 따라가고,
8줄의 희미한 산성 실선 그리드가 워드마크 뒤에 스펙트럼 기준선으로 깔린다.

루프는 화면 밖(IntersectionObserver, 120px 여백)과 숨겨진 탭
(`visibilitychange`)에서 멈춘다; `dt`는 48ms로 묶인다. 저모션에서는 통로가
일반 흐름으로 접히고, 워드마크는 구성된 후반 프레임(wdth 118, wght 760)에
주차되며, HUD는 그 값에 고정되고, 재생머리는 80%에 앉는다. 무JS: 같은 정적
상태. 왜냐하면 320vh 통로 높이는 *오직* `.typewave-js` 아래에서만 존재하기
때문이다 — 이 클래스 없이 섹션은 일반 흐름이다.

## 기법 3 — 마퀴: 엇갈리는 속도의 가사 티커

세 마퀴 띠가 들어올려진 패널 위에서 엇갈리는 속도와 방향으로 흐른다: 윗띠는
38s로 왼쪽으로, 가운데 띠는 30s로 오른쪽으로(대위법), 세 번째 띠는 *반전*된
다 — 산성 바탕에 검정 글자 — 이고 22s로 왼쪽으로, 가장 빠르고 가장 크다. 각
띠의 트랙은 복제되고, 루프는 `translateX(-50%)` 키프레임이다:

```css
.typewave-marquee__track--l { animation: typewave-marq-l 38s linear infinite; }
@keyframes typewave-marq-l {
  from { transform: translateX(0); }
  to   { transform: translateX(-50%); }
}
```

세 주기(38s / 30s / 22s)는 공통 약수가 없어, 띠들이 눈에 띄게 재동기화되는
일이 없다 — 띠 묶음은 대위법을 하는 세 독립 목소리로 읽힌다. 마퀴는 순수
CSS다: IntersectionObserver는 `animation-play-state`를 `paused`와
`running` 사이에서 토글하는 `is-running` 클래스만 바꾼다. 그래서 티커를 위한
프레임당 자바스크립트는 전혀 없다. 화면 밖에서는 일시정지로 시작하고(화면 밖
작업 없음) 화면 안에 있을 때만, 그리고 *오직* `.typewave-js` 아래에서만
작동한다. 저모션에서는 미디어 쿼리가 애니메이션을 취소하고 띠는 정적으로
앉아 완전히 읽힌다 — 가사 줄은 진짜 이중언어 마이크로카피지 로렘이
아니므로, 멈춘 티커도 여전히 읽을 수 있는 목록이다.

## 모션 수학

- **속도 정규화 2.2 px/ms.** 가벼운 휠 틱은 약 0.5로, 센 플릭은 1.0으로
  포화한다. 늘어남은 *노력*에 반응하지 픽셀 하나하나에 반응하지 않는다 —
  날것의 픽셀 속도에 반응했다면 트랙패드 스치기마다 떨렸을 것이다.
- **늘어남 감쇠 0.16/프레임 ≈ 60ms 반감기.** 풀려나는 쪽이 스크럽의 0.14/
  프레임 접근보다 일부러 빠르다: 멈추면 히어로는 제자리로 튕겨 돌아가야
  하고, 스크럽 모프는 테이프의 질량처럼 뒤로 처져야 한다. 두 다른 재질, 두
  다른 감쇠.
- **모프의 smoothstep.** `t²(3 − 2t)`가 이동을 양 극단에 집중시킨다; 선형은
  기계적으로 느껴졌을 것이고, ease-in-out cubic은 중간에 너무 오래 머물렀을
  것이다. smoothstep이 "스윕"으로 읽히는 가장 싼 곡선이다.
- **마퀴 주기 38/30/22s.** `gcd(38,30)=2`, `gcd(30,22)=2`, `gcd(38,22)=2`
  이지만 세 개를 모두 합한 *최소공배수*는 6270s ≈ 1시간 44분으로, 누구보다
  스크롤을 길게 하는 시간이다. 실제에서 띠들은 재동기화되지 않는다; 대위법은
  영구적이다.

## 성능 메모

- **속도 ref 하나, 소비자 여럿.** `useScrollVelocity`가 스크롤마다 단일
  `useRef`를 갱신하고; 히어로 글리프와 트랙리스트 헤드가 각자 `velRef.current
  `를 읽는 자기 rAF를 돌린다. 스크롤 프레임당 React 재렌더는 0 — 페이지에서
  상태가 바뀌는 건 일회성 `.typewave-js` 클래스와 IntersectionObserver의
  클래스 토글뿐이다.
- **스크럽의 rAF 조기 반환 로직은 lerp 자체에 있다** — 보이는 동안에는 항상
  적용하지만(잡고 있어도 모프가 부드러워야 하므로), 루프 자체는 화면 밖과
  숨겨진 탭에서는 완전히 멈춘다. `dt`는 48ms로 묶여 숨겨진 탭이 돌아왔을 때
  튀지 않는다.
- **마퀴는 프레임당 JS가 0이다.** `transform` 위의 CSS `linear` 키프레임;
  JS는 `animation-play-state`만 토글한다. 화면 안에 있는 쉬는 마퀴는 메인
  스레드가 아니라 컴포지터를 소비한다.
- **캔버스도, 이미지도, 오디오도 없다.** 이 엔트리의 페이로드 전체가 코드다:
  프레임당 가장 무거운 작업은 한 엘리먼트의 `fontVariationSettings`와 여덟
  글리프 스팬의 `transform`을 세팅하는 것이다. DPR은 무관하다; DPR을 신경 쓸
  것이 아무것도 없다.
- **`will-change: transform, opacity`**는 실제로 프레임마다 움직이는 분할
  글리프에만, 그리고 다른 곳에는 없이 건다 — `will-change: all` 안티패턴을
  피한다.

## 접근성 메모

- **저모션:** `usePrefersReducedMotion`(`matchMedia` 위의
  `useSyncExternalStore`)이 속도 훅을 끄고(ref가 0에 머문다), 스크럽 통로를
  일반 흐름으로 접고, 워드마크를 wdth 118/wght 760에 주차하며 HUD를 그 값에
  고정하고, 마퀴를 정지시키며, 모든 리빌을 보이게 한다. 미디어 쿼리는 또한
  글자 상승과 산성 맥동, 헤드 트래킹을 죽인다. 완성되어 읽히는 페이지가 곧
  저모션 페이지다.
- **무JS:** 숨겨진 사전 상태(`[data-reveal]`, 스크럽 통로 높이, 마퀴
  애니메이션, 글자 분할 사전 상태)는 모두 `.typewave-js` 뒤에 있다.
  자바스크립트가 없으면 페이지는 완전하고 읽을 수 있는 문서다 — 워드마크는
  쉬는 폭에 서 있고, 스크럽은 주차된 워드마크를 보여주는 보통 섹션이며,
  마퀴는 정적인 가사 줄이고, 트랙리스트는 평범한 목록이다.
- **시맨틱:** 분할 워드마크는 헤딩에 `aria-label`을, 글리프 스팬에
  `aria-hidden`을 단다; 스크럽 무대는 모프를 완전히 이중언어로 서술한
  `role="img"` 래퍼 안에 있다; 마퀴 띠는 장식용 `aria-hidden`이다(가사 줄은
  분위기이지 콘텐츠가 아니다 — 진짜 카피는 트랙리스트에 있다); 재생머리는
  장식이다.
- **터치:** 속도 늘어남과 헤드 트래킹은 정밀 포인터 전용이다(터치에서는
  페이지 스크롤 자체가 인터랙션이다); 마퀴는 스스로 움직인다; 호버 뒤에
  필수적인 것은 없다.
- **대비:** 잉크 20.1:1, 잉크-딤 6.9:1, 잉크-온-애시드 17.8:1 — 모두 바탕
  위에서 AA+ 이상; 산성(검정 위 17.8:1)은 AA 보통 텍스트를 넘기지만 본문이
  아니라 디스플레이 타입과 마크에 쓰여, 페이지가 "검정 위 초록 글자"로
  읽히지 않는다.

## 리믹스 아이디어

1. **앨범 롤.** 스크럽 엔진을 두고, 통로가 네 워드마크 — 트랙당 하나 — 를
   가로지르게 하라. 각각 다른 wdth/wght에 주차하고, 경계를 넘을 때 속도
   늘어남이 그들 *사이*로 퍼지게 하라. 트랙리스트는 옆에 챕터 띠가 된다.
2. **라이브 가사 모드.** 마퀴 띠를, 스크롤할 때 보관된 말뭉치에서 스스로를
   다시 타이핑하는 글자 분할 한 줄로 바꿔라 — 속도가 타이핑 속도를 모는,
   글자 분할과 결합된 타자기. 산성이 캐럿이 된다.
3. **듣는 비주얼라이저.** (사용자 제스처로) 옵션인 Web Audio 분석기를
   추가해 방문객의 마이크에서 값을 받고, 스크롤 속도 대신 그 RMS 빈을
   글리프별 `scaleX`에 연결하라. 워드마크가 방에서 재생 중인 무엇에 대한
   진짜 스펙트럼 분석기가 된다 — 같은 엔진, 다른 진폭 원천.
