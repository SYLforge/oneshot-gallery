# GLITCH — 기법 해설

## 핵심
실패를 마침으로 받아들이는 VFX·실험 음악 스튜디오 — 데이터모시된 타이포,
RGB 분할 워드마크, 주사선과 노이즈 오버레이, 주기적으로 뒤섞이는 손상된
ASCII. PALE.SIGNAL이 깨끗한 인광 터미널의 시라면, GLITCH는 손상되고 부서진
미학이다.

## PALE.SIGNAL과의 구별
PALE.SIGNAL = 깨끗한 인광 녹색 / 타자기 / 로그 시.
GLITCH = 손상 / RGB 분할 / 데이터모시 / 망가진 하드웨어를 의도로.
같은 패밀리 안의 정반대 레지스터.

## 기법
1. **crt-scanline** — 강한 주사선 + RGB 분할 + 노이즈(공격적; 글리치 미학).
   광과민 안전(3Hz 미만, 동작 감소 시 꺼짐).
2. **clip-path-reveal** — 섹션이 들쭉날쭉한/글리치된 clip-path 찢김으로 등장.
3. **ascii-render** — 주기적으로 뒤섞이는 손상된 ASCII 아트 / 글리치 문자.

## 접근성
동작 감소: 글리치 애니메이션 없음, 정지. 자바스크립트 없음: 완전히 읽기 가능.
AA 대비(RGB 색 검증; 부족하면 장식). 한국어 우선 이중언어. 광과민 안전: 모든
깜빡임 3Hz 미만, 동작 감소 시 제거.
