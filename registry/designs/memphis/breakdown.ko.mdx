# 멤피스 — 제작기

## 훅: 도형으로 지은 스튜디오

성수동의 두 디자이너는 멤피스를 1981년의 레퍼런스가 아니라 작업
방법론으로 다룬다. 기하는 언어고, 색은 명사며, 도형 하나하나가 왜
페이지에 남아야 하는지 스스로 말해야 한다. 이 포트폴리오가 그 증거다.
물결과 블롭으로 터지는 히어로, 선언문 마퀴, 그리고 필터를 고르면
각 도형이 제자리로 미끄러져 재정렬되는 프로젝트 그리드. 이 스튜디오의
도박은 하나, 그것도 단단한 쪽이다. 난잡함이 공예로 읽히려면 규칙이
보여야 한다. 색 다섯, 선 3px, 기법 셋 — 각 기법은 한 섹션의 머리.
할 일 없는 물결은 잘려 나간다.

## 아트 디렉션

팔레트는 일곱 토큰으로 쓴 선언문이다. 따뜻한 오프화이트 종이, 잉크,
그리고 멤피스 드럼 다섯 — 틸, 코랄, 마리골드, 코발트, 플럼. 이
팔레트를 정직하게 지키는 건 분위기가 아니라 대비 지도다. 잉크는 따뜻한
모든 바탕 위에서 6.4–15.6:1을 유지한다. 그래서 채도 높은 색들은 *잉크
글자 아래 바탕*으로 쓸 때 안전하고, 이는 멤피스가 색을 다루는 정확한
방식이다. 채움, 글자가 아니다.

틸은 종이 위 글자로는 2.4:1로 떨어져 보직을 바꿨다 — 시그니처 채움,
포커스 링, 마퀴 B줄이 그 역할이다. 코발트 바탕은 흰 글자를 얹는다
(5.68:1) 잉크 본문은 절대 안 된다(3.07:1). 코발트가 *글자로* 쓰이는
유일한 자리는 종이 위(5.1:1)이고, 그래서 모든 섹션 제목이 코발트다.
프로젝트 타일은 프로젝트 색을 크림 바탕에 12–22% 섞어(`color-mix`)
표시한다 — 타일은 그 프로젝트의 색으로 읽히되 글자는 AA를 넘긴다.
색이 세계관을 짓고 있는 셈이다.

서체 둘, 시스템 하나. Space Grotesk는 모든 로마자 글리프(디스플레이·본문·
라벨, 굵기 전 영역)를 맡고, 검은고딕(Black Han Sans)은 모든 한글을
맡는다. 디스플레이 스택은 검은고딕으로 끝나서 로마자 제목 안의 한글
글리프는 마크업 없이 저절로 검은고딕에 닿고, `:lang(ko)`이 그걸 고정하며
자간을 0으로 한다. 무겁고 기하학적인 한국어 서체가 하나뿐이라는 사실 —
그게 "스튜디오의 한국어 목소리는 로마자만큼 크고 각지다"는 설정의
증거다. 시스템 폰트 폴백이 아니라, 종이를 오려 붙인 듯한 목소리.

## 기법 1 — 클립패스 리빌: 도형의 폭발

히어로의 도형들은 페이드인하지 않는다. *잘려서* 드러난다. 기하학적
clip-path가 각 블롭·물결·지그재그를 드러내며 열리고, 그 자르는 방향이
안무의 일부다:

```css
/* styles.css — 리빌 전 상태는 JS로 게이트한다. .memphis-js가 없으면
   규칙이 적용되지 않아 JS 없는 페이지는 완성된 포스터다. */
.memphis-js .is-clipped {
  transition: clip-path 620ms cubic-bezier(0.16, 1, 0.3, 1);
}
.mp-shape--blob1 { --mp-clip-from: inset(0 0 100% 0); } /* 위에서 와이프   */
.mp-shape--sq1   { --mp-clip-from: inset(0 0 0 100%); } /* 오른쪽에서 와이프 */
.mp-shape--dot1  { --mp-clip-from: circle(0% at 50% 50%); } /* 커지기        */
```

각 대상은 자기만의 `--mp-clip-from`(시작 클립 문자열)과 `--mp-delay`를
달고 있다. `useClipReveal`이 시작 클립을 읽어 인라인으로 쓰고, 스크롤
진입(IntersectionObserver, 임계값 0.2)에서 클래스를 토글하면 CSS가
clip-path를 정지 값으로 트랜지션한다. 시작 클립의 다양성이 핵심이다.
한 방향에서 동기화된 와이프는 슬라이드 쇼처럼 읽히지만, 네 방향의
와이프에 원형 확장까지 섞이면 멤피스 특유의 조립이 눈앞에서 일어난다.

물결은 두 번째 리빌을 갖는다. `data-mp-squiggle` 패스가 스스로 그려진다.
훅이 각 패스의 `getTotalLength()`를 재서 `stroke-dasharray` /
`stroke-dashoffset`을 그 길이로 심고, 오프셋을 900ms에 걸쳐 0으로
트랜지션한다 — 물결이 주변의 클립 와이프와 맞물리며 스스로 그려진다.
구조적으로 중요한 결정은 하나, 리빌 전 상태가 전부 `.memphis-js` 뒤에
있다는 것. 자바스크립트가 꺼져 있거나 모션 최소화 설정에서는 모든 도형이
정지 클립(전체)에, 모든 물결이 완전히 그려진 상태로 있고, 페이지는
완성된 포스터다. 돌지 않은 스크립트 뒤에 아무것도 숨겨 있지 않다.

## 기법 2 — 포인터 패럴랙스: 깊이의 장

멤피스 도형들로 가득 찬 고정 필드가 무대 전체 뒤에 세 겹의 깊이
레이어로 깔려 있다. 페이지 위로 포인터가 움직이면 필드 루트에
`--mp-x` / `--mp-y`(각각 −1…1, 필드 안에서 정규화한 위치)가 쓰이고,
각 레이어는 그걸 상한이 있는 깊이 기반 이동으로 곱한다:

```css
/* 가까운 도형일수록 포인터를 더 따라가고, 먼 도형은 거의 움직이지 않는다 */
.mp-field__layer--far  { transform: translate3d(calc(var(--mp-x, 0) * 8px),  calc(var(--mp-y, 0) * 6px),  0); }
.mp-field__layer--mid  { transform: translate3d(calc(var(--mp-x, 0) * 16px), calc(var(--mp-y, 0) * 12px), 0); }
.mp-field__layer--near { transform: translate3d(calc(var(--mp-x, 0) * 26px), calc(var(--mp-y, 0) * 20px), 0); }
```

목표를 향한 lerp는 부드럽다(프레임당 `0.06`, 60fps 정규화). 그래서
도형들은 포인터를 1:1로 따라가는 게 아니라 한 박자 늦게 따라잡는다 —
추적이 아니라 패럴랙스. 배관이 정성스러운 부분이다:

```ts
// usePointerParallax — 정밀 포인터 전용. 터치는 대신 유휴 흔들림을 쓴다
if (!window.matchMedia("(hover: hover) and (pointer: fine)").matches) return;
const k = DRIFT_LERP * (dt / 16.7);
x += (tx - x) * k;
el.style.setProperty("--mp-x", x.toFixed(4));
```

싸게, 그리고 살아 있게 만드는 결정이 둘. 첫째, 깊이 이동은 *레이어
래퍼*에, 유휴 흔들림은 *도형*에 — 요소가 달라서 두 이동이 서로를
덮어쓰지 않고 합쳐진다. 둘째, 모든 도형은 서로소 주기(4.6–9.8초)로
흔들려서, 포인터 훅이 no-op이 되는 터치 기기에서도 필드가 숨 쉰다.
rAF 루프는 필드가 화면 밖(IntersectionObserver)이거나 탭이 숨겨지면
멈추고, 모션 최소화에서는 두 변수를 0으로 고정해 필드를 가만히 둔다.

## 기법 3 — FLIP 레이아웃: 재정렬되는 그리드

시그니처 섹션은 필터를 바꾸면 재구성되는 프로젝트 그리드다. *인쇄*를
고르면 인쇄 프로젝트들이 함께 미끄러져 모이고, *전체*를 고르면 다시
펼쳐진다. 움직임은 FLIP — First, Last, Invert, Play — 이고 손으로 말았다:

```ts
// ProjectFlipGrid — useLayoutEffect가 React 커밋을 감싸서, First(옛 사각형)를
// 새 레이아웃이 칠해지기 전에 잡는다.
const first = new Map<string, DOMRect>();
for (const li of tiles) first.set(li.dataset.flipKey, li.getBoundingClientRect());
// …이 시점에서 React는 이미 DOM을 바꿨다(Last = 현재 레이아웃)…
for (const li of grid.querySelectorAll(".mp-tile")) {
  const old = first.get(li.dataset.flipKey);
  if (!old) continue;                 // 새로 들어온 타일 → CSS 페이드인
  const now = li.getBoundingClientRect();
  const dx = old.left - now.left;     // Invert: 옛 자리로 되돌리는 델타
  const dy = old.top - now.top;
  el.style.transition = "none";
  el.style.transform = `translate3d(${dx}px, ${dy}px, 0)`;
}
void grid.getBoundingClientRect();     // 리플로우를 강제해 Invert를 확정
for (const { el } of movers) {         // Play: 항등으로 트랜지션
  el.style.transition = `transform 480ms cubic-bezier(0.22,1,0.36,1)`;
  el.style.transform = "";
}
```

Invert 단계가 트릭이다. React가 타일을 새 DOM 위치로 옮긴 뒤, 그 거리를
재서 곧바로 *반대*를 transform으로 건다 — 시각적으로 타일은 아직 안
움직인 것이다. 그런 다음 그 transform을 0으로 트랜지션하면, 브라우저가
타일이 옛 자리에서 새 자리로 미끄러지는 걸 애니메이션한다. 레이아웃 점프는
결코 보이지 않는다. 그리드가 스스로 재정렬되는 것처럼 읽힌다.

구조적 메모 둘. 그리드는 언제나 진짜 `<ul>` / `<li>`다. 필터링은 어떤
프로젝트가 렌더되고 어떤 순서인지만 바꾼다 — 리스트 시맨틱은 모든
재정렬에서 살아 있다. 새로 들어오는 타일(First 사각형이 없는 타일)은
FLIP하지 않는다 — 인덱스별로 50ms 엇갈림을 주는 CSS 키프레임으로
페이드인해서, 새 필터가 관련 작업이 도착하는 느낌을 준다. 모션 최소화에서는
플레이 단계 자체를 건너뛴다 — 훅이 남은 transform을 지우고 그리드가
즉시 바뀐다. React 안의 FLIP 구현이 모두 그렇듯 솔직한 트레이드오프가
하나 있다. 떠났다가 돌아오는 타일은 언마운트되고 새로 들어와서, 옛 자리를
기억하는 대신 페이드인한다.

## 모션 수학

- **클립 와이프 620ms, cubic-bezier(0.16, 1, 0.3, 1).** 강한 감속.
  도형은 리빌의 대부분을 처음 ~180ms에 끝내고 가라앉는다. 대상별로
  `--mp-delay`로 70ms 엇갈림을 줘서, 도형 여섯 개짜리 히어로가 ~1초에
  걸쳐 조립되되 슬라이드쇼처럼 동기화되지는 않는다.
- **패럴랙스 lerp 프레임당 `0.06`.** 포인터 오차의 반감기는 ~11프레임
  (~185ms) — 도형이 포인터를 한 박자 뒤따르고, 그래서 커서 거울이 아니라
  깊이로 읽힌다.
- **FLIP 플레이 480ms cubic-bezier(0.22, 1, 0.36, 1).** 오버슈트 없는
  자신감 있는 활주. 더 빠르면 여섯 타일 재정렬이 점프컷처럼 읽히고, 더
  느리면 끈적하게 느껴진다.
- **마퀴 0.05 px/ms(약 50 px/s).** 일부러 차분하게. 슬로건 하나하나 읽을
  수 있을 만큼 느리고, 살아 있다고 느낄 만큼 빠르다. 두 줄이 반대 방향으로
  가고, 밴드는 화면 밖에서 멈춘다.
- **프레스 0ms in / 140ms out, cubic-bezier(0.22, 1, 0.36, 1).** 눌러
  평평해진 도형이 손을 뗀다. 스프링 없음. 놓을 때의 오버슈트 곡선이
  성격이고, 누르는 순간의 즉시함이 규율이다.

## 성능 노트

- rAF 루프은 총 셋(패럴랙스, 마퀴, FLIP은 필터당 일회성)이고 셋 다
  스스로 꺼진다. 패럴랙스와 마퀴는 IntersectionObserver로 화면 밖과 숨겨진
  탭에서 멈추고, FLIP은 필터 변경마다 한 번 돌고 정리한다. 가만히 있는
  페이지 = 0프레임.
- 움직이는 건 전부 `transform`, `opacity`, `filter`, `clip-path`이고
  레이아웃/페인트 속성은 아무것도 움직이지 않는다. 그레인, 색 틴트, 테라조는
  한 번 래스터되는 정적 필터/그라디언트다.
- FLIP은 `useLayoutEffect`에서 사각형을 재고 플레이 전에 리플로우를 한 번
  강제한다 — 필터당 동기 레이아웃 패스 하나, 프레임당 비용이 아니다.
- `dt`는 모든 루프에서 48ms로 클램프되어, 백그라운드 탭이 깨어나도
  도형이나 티커가 순간이동하지 않는다.
- 캔버스 없음, 이미지 없음, 의존성 없음. 가장 무거운 에셋이 구글 폰트 두
  종이다. 예산 0.

## 접근성 노트

- **모션 최소화:** `usePrefersReducedMotion`(`matchMedia` 위의
  `useSyncExternalStore`)이 패럴랙스 필드를 가만히 두고, 모든 도형의 유휴
  흔들림을 세우고, 모든 클립을 전체로 열고, 모든 물결을 그려 두고, FLIP
  플레이를 건너뛰고(그리드가 즉시 바뀜), CSS 블록이 마퀴와 프레스
  트랜지션을 얼린다. 페이지가 잃는 것은 관성뿐이다.
- **No-JS:** 리빌 전 클립 상태와 물결 대시오프셋은 `.memphis-js` 뒤에
  있다. 그게 없으면 모든 도형이 정지 상태고 페이지는 완성된 포스터다.
  마퀴는 읽을 수 있는 슬로건 띠이다.
- **키보드:** 필터 칩은 진짜 `<button>`이고 활성 필터를 `aria-pressed`로
  나타낸다. 타일은 포커스 가능한 `<li>`에 설명형 `aria-label`(한글 제목,
  태그, 영문 제목, 연도)을 달았다. 포커스는 3px 틸 링 — 잉크 푸터 위에서는
  보이도록 마리골드로 바뀐다.
- **터치에서의 패럴랙스:** 훅은 hover + 정밀 포인터 전용이다. 터치에서는
  필드의 유휴 흔들림이 생명을 가져온다. 필수적인 것은 포인터 뒤에 숨겨
  있지 않다.
- **FLIP 시맨틱:** 그리드는 언제나 진짜 리스트다. 필터링은 `<ul>` / `<li>`
  구조를 절대 깨지 않아서 접근성 트리와 탭 순서가 모든 재정렬에서 살아
  있다.
- **대비:** 잉크/종이 15.6:1, 잉크/마리골드 11.3:1, 잉크/틸 6.59:1,
  잉크/코랄 6.40:1, 코발트 글자/종이 5.1:1, 흰 글자/코발트 5.68:1,
  플럼/종이 7.0:1 — 기능적 조합 전부가 그레인 최악 케이스를 포함해도 AA를
  넘는다. 틸 글자(2.4:1)와 코발트 위 잉크(3.07:1)는 오직 바탕으로만
  존재하고, 기능적 글자로는 쓰이지 않는다.

## 리믹스 아이디어

1. **테라조 타일 가게.** FLIP 그리드는 그대로 두고 프로젝트를 수제
   시멘트 타일 문양으로 바꾼다(각 타일은 생성형 테라조 SVG). 필터는 색
   가족이 되고, 반점 디스크 마크는 스튜디오 자체 칩 설정기가 된다.
   물결 리빌은 타일 가장자리가 잘려 들어오는 모습이 된다.
2. **멤피스 레코드 라벨.** 그리드는 디스코그래피가 되고(필터는 포맷:
   7인치 / 12인치 / 카세트), 각 타일의 모티프는 재킷의 시그니처 도형이
   되며, 마퀴는 투어 일정을 양방향으로 돌린다. 코발트 스튜디오 패널은
   라이너 노트 에세이가 된다.
3. **어린이박물관 전시 안내.** 같은 도형 시스템에 더 따뜻한 목소리.
   FLIP 그리드는 전시를 구역별로 정렬하고, 패럴랙스 필드는 갤러리의
   떠다니는 길안내 도형이 되며, 물결 리빌은 각 전시 카드가 팝업북
   페이지처럼 펼쳐지는 모습이 된다.
