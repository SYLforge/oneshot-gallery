# 피다 BLOOM — 제작기

## 훅: 피어나는 일로서의 페이지

서귀포의 작은 향원 하나는 병을 팔지 않는다. 그것이 파는 건 *피어나는
일* — 향이 밝은 탑에서 꽃의 하트를 거쳐 뿌리의 베이스로 펼쳐지는, 그
반나절의 시간이다. 페이지는 그 반나절을 예행연습한다. 따뜻한 크림빛
종이 한 장에 도착하면, 잉크 선의 식물이 줄기부터 한 획씩 스스로를
그린다 — 19세기 향수 일지를 채우는 조향사의 도판처럼. 선 뒤로 분홍빛
수채가 바깥으로 번지며 제 경계를 찾는다 — *젖은 종이 위의 잉크*, 이
페이지 이름의 행위 — 그리고 한 송이 꽃이 스크롤을 따라 꽃잎을 하나씩
편다. 하우스의 시그니처 향이, 문자 그대로, 펼쳐지는 것이다.

디자인의 도박: 손으로 그린 SVG만이 유일한 이미지인 라이트 페이지에서,
*번지고 가라앉는 안료*가 어떤 사진보다 더 깊은 분위기를 만들어 낼 수
있다 — 향이 피어난 사진은 이미 끝난 일의 기록이지만, 이 페이지는 지금
일어나고 있는 일이니까.

## 아트 디렉션 — 사쿠라와의, 짐을 진 구별

이 엔트리는 `ink-bloom` 패밀리의 세 가지 중 두 번째다. 패밀리의 명제
(*잉크 → 블룸*)는 둘 다 지키되 — 도구를 의도적으로 다르게 했다. 그래서
회색 음영 스크린샷만 봐도 둘을 헷갈리지 않는다. 사쿠라(첫 번째)는
검은 캔버스에 벚꽃 파티클을 흩뿌린다: 밤, 떨어지는 꽃잎, 검정 위의
분홍. 피다는 따뜻한 크림 종이에서 SVG 선화가 스스로를 그리고 그 뒤로
수채가 번지는 페이지다: 낮, 조향사의 도판, 종이 위의 초록과 분홍.
사쿠라의 블룸이 *움직이는 사물*(꽃잎이 흩날리고 진다)이라면, 피다의
블룸은 *종이 위의 행위*(안료가 번지고 가라앉는다)다. 같은 패밀리,
정반대의 시간대, 다른 악기.

팔레트가 그것을 지킨다. 바탕은 따뜻한 크림 `#faf3e8`(종이, 결코 흰색이
아니다), 목소리는 잉크 `#2a2620`(12.4:1, 그림펜 자체의 색), 그리고
클릭을 청하는 유일한 색으로 식물 초록 `#3d6b3a`(6.9:1) 하나뿐이다 —
워드마크, 섹션 번호, CTA, 포커스 링, 가장 깊은 줄기에만 나타난다.
세이지 `#8aa67a`와 블러시 `#d98a9e`는 페이지에서 가장 예쁜 두 색이지만
둘 다 AA에 미치지 못한다(2.4:1, 1.9:1). 그래서 목소리가 아니라
안료로만 쓴다: 잎 채우기와 유일한 꽃잎 수채. 보조 텍스트는 대신 파생
토큰이 맡는다 — `bark #5c554a`(5.7:1).

서체 둘은 손이 다르다. 코모란 가라몬드는 조향사의 라틴 손 — 워드마크,
섹션 제목, 그리고 모든 이탤릭 방백(공식의 여백에 적어둔 줄). 본명:
Noto Serif KR은 모든 한글과 페이지의 제1언어를 담는 땅이다. 디스플레이
스택을 `Cormorant Garamond, Noto Serif KR, serif` 순서로 두었기에
거대한 '피다'는 마크업 없이 라틴 서체를 통과해 Noto Serif KR에
도착한다 — 숲(SUP)이 고운돋움으로 떨어지는 것과 같은 우연이지만,
정반대의 효과로: 둥근 산세리프가 아니라 붓의 세리프.

## 기법 1 — 스스로를 그리는 식물 (svg-line-draw)

히어로의 식물은 손으로 쓴 SVG 도판이다 — 두 갈래 줄기와 네 잎, 꽃받침,
다섯 꽃잎의 봉오리 하나를 가진, 꽃 피는 줄기 하나. 숲(SUP)이 절차적
L-시스템을 기른 것과 달리, 피다의 선화는 글자 그대로의 패스 데이터다.
모듈 로드 때 한 번 그려지고 서버와 클라이언트가 동일하므로 하이드레이션
차이는 구조적으로 불가능하다.

재미있는 부분은 그리기 시계다. 모든 획은 공유된 0→1 시계 위에서 자기만의
창 `[d0, d1]`을 갖는다 — 서사의 *어느 지점*에서 그려지는지를 기록한다:
줄기는 `0.00–0.18`, 가지는 `0.18–0.34`, 잎은 `0.30–0.58`, 봉오리와
꽃은 `0.58–1.00`. 모든 패스에 `pathLength={1}`을 주어 대시 계산이 실제
길이를 무시하게 하고, 그러면 단 하나의 CSS 변수가 도판 전체를 그린다.

```css
/* styles.css — 변수 하나, 약 40개의 사적 획 타임라인 */
.bloom-draw__stroke {
  stroke-dasharray: 1 1;
  stroke-dashoffset: clamp(
    0,
    calc((var(--d1, 1) - var(--bloom-draw, 1)) /
         (var(--d1, 1) - var(--d0, 0))),
    1.02
  );
}
```

`--bloom-draw`가 0이면 모든 오프셋은 `(d1 − 0)/(d1 − d0)` — 큰 양수로,
1.02에 고정되어, 대시가 완전히 밀려 있고 획은 보이지 않는다. 시계가
오르면 각 획의 오프셋이 자기 창 안에서 0을 지나고, 획은 시작점에서부터
*그려지듯* 나타난다. rAF 훅(`useLineDraw`)이 변수를 ~2.4초에 걸쳐 0.7까지
이징하고, 나머지 30%는 스크롤이 채운다.

```ts
// useLineDraw.ts — 인트로 + 스크롤, 결코 튀지 않도록 lerp
const intro = easeOut(Math.min((now - born) / INTRO_MS, 1)) * INTRO_REACH;
const scroll = Math.min(window.scrollY / (window.innerHeight * SCROLL_SPAN), 1);
const target = Math.min(1, intro + (1 - INTRO_REACH) * scroll);
const next = value + (target - value) * DRAW_LERP * (dt / 16.7);
```

접근성 이야기를 짊어지는 디테일 셋. 첫째, 폴백은 `var(--bloom-draw, 1)`이라
JS가 없거나 모션 축소일 때 방문자는 다 그려진 도판을 본다 — 벌거벗은
줄기가 아니라. 둘째, 숨겨진 상태의 오프셋이 1.0이 아니라 1.02에
고정되므로, 둥근 선 끝이 획의 밑둥에 유령 점을 남기지 않는다. 셋째,
같은 훅 인스턴스가 센트 노트 섹션의 카드마다 재사용된다 — 각 도판은
스크롤하여 들어갈 때마다 독립적으로 그려져서, 하나의 동기화된 애니메이션이
아니라 일지 속의 세 개의 별도 삽화처럼 읽힌다.

## 기법 2 — 경계를 찾는 잉크 (feturbulence-texture)

이것이 페이지 이름의 행위이자, 사쿠라의 블룸과 피다의 블룸을 가르는
것이다. 사쿠라는 *파티클을 흩뿌려* 피어난다 — 움직이는 사물. 피다는
*안료를 번지게 해* 피어난다 — 종이 위의 행위. 작동 원리는 각 수채
수세물 형태 위에 얹은 SVG `feTurbulence + feDisplacementMap` 필터로,
그 `scale` 속성이 화면에 들어올 때 ~62에서 0까지 움직인다.

```ts
// useWashSettle.ts — 수채는 "아직 젖은" 상태로 시작해 가라앉는다
const settle = (svg) => {
  const fe = maps.get(svg);
  const t0 = performance.now();
  const tick = (now) => {
    const p = Math.min((now - t0) / SETTLE_MS, 1);
    const ease = 1 - (1 - p) ** 3;        // cubic out — 느린 블룸
    fe.setAttribute("scale", String(WET_SCALE * (1 - ease)));
    if (p < 1) rafs.add(requestAnimationFrame(tick));
  };
  rafs.add(requestAnimationFrame(tick));
};
```

`scale=62`일 때 프랙탈 노이즈가 수세물의 각 픽셀을 노이즈의 R/G 채널이
정하는 방향으로 최대 62단위까지 밀어낸다 — 색이 노이즈 장에 번져,
경계가 녹아, *여전히 젖어 있고, 여전히 움직이는* 것처럼 읽힌다.
스케일이 0으로 이징하면서 변위가 무너지고 수채는 마침내 (거의) 또렷한
경계에 가라앉는다 — *잉크가 제 경계를 찾은 것이다*. 결정적으로, 움직이는
것은 `scale`뿐이다. 난류의 `baseFrequency`와 `seed`는 결코 변하지 않아,
노이즈 텍스처는 브라우저가 한 번만 계산하고 매 프레임은 변위 패스만
지불한다. 수채마다 별도의 rAF가 돌고, 모두 IntersectionObserver로
묶여 있어 화면 밖 비용은 0이다.

이 필터 바로 옆에 이 페이지의 핵심 공예 결정이 있다: 식물 **선화**(줄기,
잎, 꽃잎)는 변위 필터가 *없는* 순수 SVG 획이다. 선 아래의 수채만
번지고, 그어진 선은 또렷하게 머문다. 그 대비 — 또렷한 선, 번진 수채 —
*곧* 수채화라는 매체이며, SVG 기능 두 개와 rAF 루프 하나로 재현했다.

두 번째, *정적인* `feTurbulence`(baseFrequency 0.9, seed 7)가 전체
페이지 위에 ~4% 크림-온-크림으로 `mix-blend-mode: multiply`에 고정되어
있다 — 종이 결. 결코 움직이지 않는다; 크림이 납작한 `#fff`로 읽히지
않게 할 뿐. 케무리의 와시 결(따뜻한 장 위의 잉크빛 노이즈)과 구별하라:
피다의 결은 크림-온-크림이며, 더 가볍고, 직물이 아니라 종이다.

## 기법 3 — 당신과 함께 피는 꽃 (scroll-scrub-pinned)

시그니처 모먼트. 260vh 높이의 `position: sticky` 섹션이 하나의 핀된
뷰를 붙잡고, 섹션을 지나는 스크롤 진행도가 `--bloom-open`을 0에서 1로
몬다. 큰 꽃 한 송이 — 바깥 8, 안쪽 5의 꽃잎에 금빛 원반과 수술 여섯
점 — 은 프레임에 고정된 채, rAF 훅(`useScrollProgress`)이 변수를
스크롤 목표를 향해 lerp한다.

```ts
// useScrollProgress.ts — 핀된 섹션의 스크롤이 변수 하나로 대응된다
const computeTarget = () => {
  const rect = el.getBoundingClientRect();
  const total = rect.height - window.innerHeight;
  if (total <= 0) { target = 1; return; }
  const traveled = Math.min(Math.max(-rect.top, 0), total);
  target = traveled / total;
};
```

그러면 CSS가 그 변수 하나를 모든 꽃잎의 transform으로 바꾼다. 바깥 고리가
먼저 열리고 안쪽 고리가 나중에 열려, 꽃이 바깥에서 안으로 펴지듯 읽힌다 —
작약이 피는 방식 그대로.

```css
/* styles.css — 바깥 고리는 시계의 0.0–0.8에서 핀다 */
.bloom-sig-ring--outer .bloom-sig-petal {
  --bloom-local: clamp(0,
    calc((var(--bloom-open, 1) - var(--bloom-pstart) * 0.5) / 0.8), 1);
  transform-origin: 300px 300px;
  transform: rotate(calc(-8deg * (1 - var(--bloom-local))))
             scale(calc(0.42 + 0.58 * var(--bloom-local)));
  opacity: calc(0.4 + 0.6 * var(--bloom-local));
}
/* 안쪽 고리는 0.35–0.95에서 — 더 늦게 */
.bloom-sig-ring--inner .bloom-sig-petal {
  --bloom-late: clamp(0,
    calc((var(--bloom-open, 1) - 0.35 - var(--bloom-pstart) * 0.04) / 0.6), 1);
  transform: rotate(calc(-10deg * (1 - var(--bloom-late))))
             scale(calc(0.36 + 0.64 * var(--bloom-late)));
}
```

여기서 선화는 *완전히 미리 그려져* 있다 — 이 섹션이 다루는 것은 그림이
아니라 개화다(그림은 히어로의 몫이었다). 모든 꽃잎 패스는 첫 페인트부터
DOM에 존재하고, 변하는 것은 오직 `transform`과 `opacity`, 전부
컴포지트 단계라 레이아웃은 없다. lerp(프레임당 0.14, 반감기 약 5
프레임)가 지터 없이 스크럽되게 한다: 빨리 스크롤하면 빨리 피고, 천천히
하면 천천히 피며, 다시 위로 올리면 꽃이 다시 닫힌다. 꽃 뒤의 분홍 수세
원반은 개화를 따라 채워지고(불투명도), 핀된 뷰의 아래쪽 머리결 진행
막대가 `--bloom-open`을 문자 그대로 따라간다.

접근성 계약: 꽃 옆의 카피("스크롤하면, 하우스의 향이 꽃잎을 하나씩
펼칩니다")는 평범한 항상 보이는 텍스트라, 의미가 모션에 의존하지
않는다. 폴백 `var(--bloom-open, 1)`은 JS가 없는 방문자에게 완전히 핀
꽃을 보여주고, 모션 축소에서는 섹션 전체가 `height: auto; position:
relative`로 무너져 아무것도 스크롤 뒤에 가려지지 않는다.

## 모션 수학

- **그리기 lerp 프레임당 0.12**(60fps 정규화): 반감기 약 5.4 프레임 ≈
  90ms. 스크롤이 문지르는 느낌이 아니라 그리는 느낌이 들 만큼 반응적이되,
  줄기가 튀어 나타나지 않을 만큼 느리다.
- **개화 lerp 프레임당 0.14**: 반감기 약 4.6 프레임 ≈ 77ms. 그리기보다
  한 뼘 더 빠른데, 꽃이 피는 일이 줄기를 그리는 일보다 조금 더 간절해야
  하기 때문이다.
- **수채 가라앉음 1700ms cubic-out**: 변위가 `1 − (1−p)³` 곡선을 따라
  무너지므로, 블룸의 대부분은 처음 600ms 안에 일어나고 마지막 1100ms는
  경계가 스스로를 찾는 시간이다 — 느린 꼬리가 *멈춤*이 아니라 *마름*으로
  읽힌다.
- **앰비언트 주기 11초 / 19초**(선화 흔들림 / 햇살 호흡)는 공약수를
  공유하지 않아 — 페이지가 눈에 띄게 루프하는 일이 없으며, 이것이
  "살아 있되 붐비지 않은" 대부분이다.
- 리빌 이징 `cubic-bezier(0.25, 0.8, 0.3, 1)`은 900ms의 첫 1/3에서
  이동의 약 65%를 커버한다; 18px 이동과 함께 꼬리는 아래픽셀로
  가라앉아, 느림이 답답이 아니라 차분함으로 읽힌다.

## 성능 메모

- 프레임당 한 번의 `setProperty`가 히어로의 약 40개, 센트 노트 카드
  하나당 약 10개의 SVG 획을 몬다; 브라우저가 스타일 재계산을 묶어
  처리하고 `stroke-dashoffset`/`opacity`/`transform`은 모두 페인트·컴포지트
  단계라 — 그리는 동안 레이아웃은 결코 돌지 않는다.
- `useWashSettle`은 수채마다 하나의 `feDisplacementMap` `scale`
  *속성*만 움직인다; 난류 장은 브라우저가 한 번 계산하므로, 매 프레임은
  활성 수채당 변위 패스 하나뿐 — DPR 2에서도 가볍다.
- 핀된 꽃은 13개의 `<g>` 요소 위에서 변수 하나로 도는 순수 CSS transform
  수학이다 — 꽃잎마다 rAF가 아니라 섹션 전체를 위한 rAF 하나이며, 그
  루프도 화면 밖(IO)과 숨겨진 탭에서 멈춘다.
- 세 갈래 훅(그리기, 수채, 개화) 모두 화면 밖에서 스스로 멈추고 언마운트
  때 옵저버와 리스너를 정리한다.
- 식물 패스는 모듈 로드 때 한 번 쓰여(런타임 비용 없음) 서버와 클라이언트가
  공유한다 — 하이드레이션 차이는 구조적으로 불가능하다.

## 접근성 메모

- **모션 축소:** `usePrefersReducedMotion`(matchMedia 위의
  `useSyncExternalStore`)가 세 갈래 모션 훝을 모두 끈다; CSS 폴백이
  모든 것을 정물의 구도 위에 내려놓는다 — 모든 선은 다 그어지고
  (`--bloom-draw: 1`), 모든 수채는 가라앉고(변위 마크업 `scale="0"`),
  핀된 꽃은 완전히 피어 있으며(`--bloom-open: 1`) 핀된 섹션은 auto
  높이로 무넄져 아무것도 스크롤 뒤에 가려지지 않는다.
- **JS 없음:** 리빌 전 숨김 상태는 `.bloom-js` 아래에만 존재하고, 모든
  애니메이션 값은 끝난 상태의 폴백을 갖는다. 소스 보기는 완전하고, 다
  그어지고, 다 핀 페이지를 보여준다 — SSR 프레임 자체가 완성된 페이지다.
- **의미론:** 식물 SVG는 `aria-hidden`이다(제목이 의미를 짊어진다); 핀된
  섹션의 센트 노트 `<dl>`과 모든 카피는 진짜 시맨틱 콘텐츠다; CTA와
  푸터 링크는 네이티브 앵커로, 식물 초록 `:focus-visible` 링과 부드러운
  헤일로를 갖는다.
- **대비:** 크림 위에서 잉크 12.4:1, 식물 6.9:1, bark 5.7:1; 세이지(2.4:1),
  블러시(1.9:1), 골드는 결코 아무것에 이름표를 붙이지 않는다 — 안료다.
- **키보드:** CTA → 푸터 링크가 차례로 도달하며, 각각 포커스 링을 갖는다.

## 리믹스 아이디어

1. **다원(茶院).** 향수 전제를 한국 다원으로 바꿔라: 식물은 찻잎(동백)이
   되고, 세 센트 노트는 세 가지 우리(첫·두·세 번째 우림)가 되며, 핀된
   꽃은 뜨거운 물에서 펴지는 잎 하나가 된다 — 같은 스크롤 스크럽이되,
   방사형 꽃이 아니라 수직 잎 형태 위에서. 팔레트: 크림 → 한지, 식물 →
   더 깊은 차록(茶綠).
2. **서예 공방.** 수채를 완전히 빼고, 선화만 남겨 각 획에 서예적
   필압 변화를 입혀라(겹쳐 그은 여러 패스와 `stroke-linecap`으로 경로를
   따라 `stroke-width`를 변동). 핀된 모먼트는 한 자(字) 하나가 정해진
   순서대로 한 획씩 스스로를 그리는 것이 된다. 팔레트: 크림 위 먹색
   단색, 인장주 한 점.
3. **식물 일지(다크).** 깊은 식물록 바탕(`#1a2418`)에 크림 선화로 뒤집어라
   — 밤에만 피는 사촌. 수채 수세물은 생물발광이 되고(불투명도를 높이고,
   가라앉는 대신 변위를 지속), 핀된 꽃은 밤에만 피는 월광화가 된다.
   뒤집어도 초록-크림을 지켜 분홍으로 가지 않음으로써 사쿠라와 구별된다.
