# 벚꽃 — 기술 해설

## 이 페이지가 하는 일

이 페이지는 단 한 가지를 하고, 끝까지 그것만 한다. 깊은 밤하늘에서 검은
먹방울이 떨어져, 보이지 않는 수면에 닿고, 벚꽃잎으로 피어난다. 그 꽃잎은
당신의 손이 만드는 바람에 기울고, 천천히, 진다. 그것이 전부다 — *잉크와
개화*. 페이지는 그 주위를 꾸미려 들지 않는다. 무언가를 파는 상점은 여기에
없다; 페이지 자체가 곧 작품이며, 일본의 *것의 아와레*(もののあわれ) —
덧없는 아름다움에 대한 다정하고 감사한 슬픔 — 를 무대 위에 올린다. 이
정원의 꽃잎은 하나같이 태어나고, 흩날리고, 잊힌다. 페이지는 그 잊힘을
연출할 뿐이다.

이 엔트리는 [oneshot-sakura](https://oneshot-sakura.vercel.app/)에 대한 이
갤러리의, 정직하게 표기된 답이다 — 잉크가 꽃으로 피어난다는 그 레퍼런스의
전제가 `ink-bloom` 패밀리를, 그리고 부분적으로는 이 갤러리 자체를
영감했다. 논지는 같은 전제를 처음부터 다시 쓰는 것이다: 삼언어, 설치
가능, 전체 소스 포함, MIT, 그리고 무료. 레퍼런스가 하나의 히어로를
보여준다면, 이 페이지는 화면 전체를 — 토큰 시트와 이 정직한 프롬프트까지
함께 — 내놓는다.

디자스트의 베팅은 와시수묵 패밀리의 기함 KEMURI가 연기를 위해 했던 것과
같은 것을, 반대 방향으로 되풀이하는 것이다. *시뮬레이션된* 개화 — 실제
유체 물리의 컬 노이즈 장으로 수송되는 — 가 떨어지는 꽃잎의 어떤 영상보다
더 많은 것을 전한다. 영상은 끝나지만, 이 정원은 끝나지 않기 때문이다.

## 아트 디렉션

잉크·블룸은 밤의 깊이에서 결정된다. 바탕은 깊은 먹색(`#0e0a0f`),
말하는 목소리는 가장 옅은 붉은빛을 더한 거의 하양(`#f6eef0`, 17.2:1
— AAA), 그리고 강조색은 단 하나 — 개화 분홍 `#e8869e` — 로, 꽃잎이
살아 있는 자리에만 나타난다: 키커, 시의 번호, 포커스 링, 선택 영역,
카드 테두리. 따뜻한 점 하나, 금색 `#c9a85a`는 정확히 세 곳에만 —
히어로의 가는 줄, 인장, 흩날리는 꽃가루 한 알. 두 번째 따뜻한 색이나
그라디언트 덩어리가 하나라도 더 들어오면, 페이지는 스크린세이버가
된다.

이 패밀리를 까다롭게 만든 제약은, KEMURI의 그것과 정반대다. KEMURI의
장작빛은 와시 위에서 AA에 미치지 못해(2.9:1) 꺼줘야 했지만, 여기서는
개화 분홍 강조색이 먹밤 바탕 위에서 7.8:1을 기록한다 — 본문 텍스트
기준으로도 AA를 넘긴다. 그래서 분홍은 어디서든 말하도록 허락되었고,
다크 테마 치고는 유난히 너그러운 팔레트가 됐다. `blossom-deep #c75a76`
(패널 위 4.6:1)은 올려 놓은 잉크 패널 위에서만 — 본래의 분홍이 너무
밝게 읽히는 그 한 곳에만 — 쓰인다. 페이지는 단 한 번도 반전하지 않는다
(KEMURI는 다크룸 한 번 뒤집었지만, 여기서는 어둠이 곧 집이다).

트라이타이포그래피는 뻔한 삼언어의 함정을 거부한다. 시포리 민초가
모든 일본 글리프를 — 세로 제목 桜花, 시의 번호 一二三四, 인장 — 받는데,
시포리는 세로쓰기를 먼저 두고 그려낸 글꼴이기 때문이다. 본고딕 세리프가
한국어 메인 목소리, 곧 실제로 말하는 목소리(벚꽃, 시의 본문, 서두)를
맡는다. 코모란 가라몬이 라틴 자막 — 워드마크, 그 아래 영어, 숫자 — 을
맡는다. 적층 순서(`코모란, 본고딕 세리프, 시포리, serif`) 덕분에
한글과 한자는 라틴 글꼴을 거쳐 제 것으로 떨어지는 데 마크업이 필요
없다. 세 언어는 크기가 아니라 역할로 구분된다: 한국어는 말하고,
일본어는 장식하고, 영어는 번역한다.

## 기법 1 — 잉크에서 꽃으로의 개화 (canvas-particles)

떨어지는 꽃잎을 나이브하게 애니메이션하려면, 각 입자에 무작위 배회와
중력 틱을 주면 된다. 그러나 그것은 색종이나 눈으로 읽힌다 — 독립된
무작위 걸음에는 *구조*가 없고, 봄 공기 위의 진짜 꽃잎은 함께 움직이며,
압축 불가능한 흐름 속에서 소용돌이가 생겼다가 머물기 때문이다. 유체
솔버 없이도 그 모든 것을 얻을 수 있고, 이 페이지는 KEMURI가 연기에 쓰는
바로 그 기교를 — 아래로 향하게 뒤집어 — 되풀이한다.

부드러운 스칼라장 ψ(*퍼텐셜*)를 하나 잡고, 속도를 그 회전된 기울기로
정의하라:

```ts
// useBloomCanvas.ts — 발산이 없는 흐름: 속도 = (∂ψ/∂y, −∂ψ/∂x)
const cx =
  (psi(x, y + CURL_EPS, t) - psi(x, y - CURL_EPS, t)) / (2 * CURL_EPS);
const cy =
  -(psi(x + CURL_EPS, y, t) - psi(x - CURL_EPS, y, t)) / (2 * CURL_EPS);
```

이것은 ψ의 2차원 *컬*이며, 회전된 기울기는 정의에 의해 발산이 없다:
∂vx/∂x + ∂vy/∂y = 0. ψ에 어떤 노이즈를 부어 넣든, 결과 흐름은 면적을
보존한다 — 이 흐름으로 수송되는 꽃잎은 퍼텐셜의 등고선을 따라 영원히
돌되, 결코 압축되지 않는다. 이 성질 하나가, 바람 위의 꽃잎과 색종이
위의 꽃잎을 가른다.

ψ는 시드가 있는 값 노이즈 두 옥타브(특징 크기 ~170px, ~64px)이며,
장 자체가 왼쪽과 위로 흐른다:

```ts
// useBloomCanvas.ts — 바람장이 꽃잎과 함께 이동한다
function psi(x: number, y: number, t: number): number {
  const xr = x + t * FIELD_DRIFT_X; // −10 px/s
  const yr = y + t * FIELD_DRIFT_Y; // −14 px/s
  return (
    valueNoise(xr * GUST_LARGE, yr * GUST_LARGE) - 0.5 +
    (valueNoise(xr * GUST_SMALL + 23.1, yr * (GUST_SMALL * 1.3) + 7.7) - 0.5) * 0.4
  );
}
```

이 흐름이 없다면, 꽃잎은 얼어붙은 난류를 헤에치는 꼴이 되어 밧줄을
기어오르는 듯 보인다; 흐름이 있으면, 돌풍마다 자기 꽃잎과 함께 태어나고,
이동하고, 죽는다. (KEMURI의 연기는 자기 장을 26 px/s로 위로 올리지만,
이 정원은 장을 (−10, −14)로 왼쪽-위로 흘려보낸다 — 봄 날씨가 실제로
움직이는 방향이다.)

이 페이지가 KEMURI와 갈라지는 지점은 *발원*이다. 연기는 향로 입에서
솟는 끊임없는 기둥이지만, 여기의 꽃잎은 *사건* 속에서 태어난다. 먹방울이
중력 아래로 떨어지고(580 px/s², 종단 속도 480 px/s), `y = 0.42·H`인
수면을 지나는 순간 튀어오르고(4–7개의 미세 방울이 위로, 수명 0.5초),
**피어난다** — 8–14개의 꽃잎 입자가 바깥으로 40–90 px/s의 속도와
각도 퍼짐으로 솟아오르며, 그 뒤 컬 장에 맡겨진다:

```ts
// useBloomCanvas.ts — 수면 위의 개화
const bloom = (x: number) => {
  const n = BLOOM_MIN + ((rand() * BLOOM_SPREAD) | 0);
  const baseAngle = rand() * Math.PI * 2;
  for (let k = 0; k < n; k++) {
    // 죽은 꽃잎 슬롯을 찾아 바깥으로 향하는 새 꽃잎으로 재활용
    const ang = baseAngle + (k / n) * Math.PI * 2 + (rand() - 0.5) * 0.8;
    const spd = BURST_VEL_MIN + rand() * BURST_VEL_SPREAD;
    parts[o] = x; parts[o + 1] = waterY;
    parts[o + 2] = Math.cos(ang) * spd;
    parts[o + 3] = Math.sin(ang) * spd * 0.6 + PETAL_SINK; // 가라앉지, 뜨지 않는다
    // ...
  }
};
```

꽃잎은 −22 px/s로 가라앉는다 — 벚꽃은 *떨어진다*, 뜨지 않는다 — 이것이
KEMURI의 +46 px/s 연기 부력을 뒤집은 것이다. 꽃잎은 1.8 s⁻¹로 장을 향해
완화되고(복종이 아니라 관성), 7–13초를 살고, 제곱근 곡선 위에서
사라져서 "겨우 남은" 지점을 일찍 넘기고 평생을 속삭임으로 보낸다. 미리
그려둔 세 가지 색의 스프라이트(갓 핀 분홍, 한창 핀 꽃, 옅은 가장자리)가
입자마다의 음영 없이도 다양함을 준다; 꽃잎 하나는 5갈래 노치 진 꽃잎
경로를 그린 스프라이트의 `drawImage` 한 번이다. 첫 화면이 그려지기 전에
시스템은 90스텝의 90ms 사전 이동을 돌려, 정원이 심어지는 장면을 결코
보여주지 않는다 — 당신이 도착하기 전에 이미 피어 있었다.

## 기법 2 — 손을 향해 기울이는 바람 (pointer-parallax)

두 외부 힘이 정원을 구부리되, 결코 조종하지는 않는다.

- **포인터.** 커서를 향한 상한있는 수평 당김(≤ ±70 px/s)이, 비대칭
  lerp를 가진 에너지 값으로 열린다 — 어택 0.06, 릴리즈 0.02 (60fps
  기준). 꽃잎은 손을 약 4분의 1초 안에 알아채고, 잊는 데 3초가 걸린다.
  당김의 도달거리는 포인터로부터의 수직 거리에 따라 가우시안으로
  줄어들어(H 위), 정원 위의 손은 아래의 꽃잎을 거의 흔들지 않는다 —
  바람에는 국소성이 있다. 터치이거나 2.6초의 정적이 지나면, 에너지는
  0으로 줄고 자율 미풍이 다시 맡는다.
- **클릭·탭.** pointer-down은 잉크 낙하 요청을 큐에 밀어 넣고, 캔버스의
  rAF 루프가 그것을 비운다: 탭한 x 위, 스테이지 꼭대기에서 새 먹방울이
  떨어지며 당신이 두드린 자리에서 피어난다. 이것이 시그니처 상호작용이다
  — 당신이 잉크를 떨어뜨리면, 정원이 대답한다. 큐는 결코 합쳐지지
  않아, 빠른 두 번 탭은 두 번의 개화를 낳는다.

```ts
// usePointerInk.ts — 클릭/탭은 잉크 낙하를 큐에, pointer-move는 바람 편향을 기록
const onPointerDown = (ev: PointerEvent) => {
  const { x } = localXY(ev.clientX, ev.clientY);
  drops.current.push({ x, y: 0, t: performance.now() });
};
```

포인터 하위 시스템 전체는 React를 한 번도 다시 그리지 않는다.
`usePointerInk`는 날것의 위치와 에너지를 ref에 쓰고; 캔버스의 rAF 루프가
그것을 읽어 어택/릴리즈를 프레임률에 맞게 정규화한다. 이것은 KEMURI의
`useScrollVelocity`가 스크롤에 쓰던 패턴을 포인터 공간으로 옮긴 것이다.

## 기법 3 — 읽기와 함께 도착하는 꽃잎 (scroll-scrub-pinned)

시 구간은 이 페이지의 영혼이며, 개화가 스크롤에 결합되는 유일한
자리다. 이 구간은 약 260vh로 높고, 안쪽 무대는 `position: sticky;
top: 0; height: 100svh`라, 네 편의 시가 당신이 그 사이를 스크롤하는
동안 제자리에 *핀* 된다. `useScrollProgress` 훅이 구간의 박스를
뷰포트 위쪽에 대해 재어 ref에 기록하고(React 재렌더링 없음), 두 소비자가
그 ref를 읽는다.

1. **개화 캔버스**(`progress` prop을 통해). `raw`가 0→1로 가면서 자율
   낙하 간격이 짧아지고(`AUTO_DROP_INTERVAL / (1 + p · 2.2)` — 풀
   진행에서 ~3.2배 더 많은 낙하), *밀도 바닥*이 어느 순간에든 최소
   `progress · 0.7 · count`개의 꽃잎이 살아 있도록 강제하며, 죽은
   슬롯을 재활용해 그것을 채운다. 그리하여 꽃잎이 당신이 시를 읽는
   만큼 *쌓인다* — 정원이 꽃으로 차오른다 — 그리고 당신이 되감으면,
   바닥이 내려가고 꽃잎이 자연스럽게 지면서 사라진다. 꽃잎은 영원하지
   않다; 그것이 것의 아와레의 전부다.

2. **시 교차 페이드.** 아주 작은 rAF 루프가 날것의 진행도를 매끄럽게
   lerp(프레임률 정규화, 8 s⁻¹)하고, 활성 인덱스가 바뀔 때마다 시
   스택에 `data-active="<i>"`를 쓴다. CSS가 그것에 맞춰 매칭한다:
   스택의 `data-active`와 같은 `data-i`를 가진 시가 opacity 1이 되고,
   나머지는 사라지며 떠오른다. 같은 변경이 `aria-hidden`을 설정해,
   스크린 리더가 항상 보이는 시를 읽도록 한다 — 스크럽은 시각적일
   뿐 아니라 의미론적이다.

```ts
// VerseScrub.tsx — 매끄러워진 진행도가 캔버스와 시 교체를 모두 모는다
smoothed.current += (raw - smoothed.current) * (1 - Math.exp(-dt * 8));
const active = verseForProgress(smoothed.current);
if (stack.getAttribute("data-active") !== String(active)) {
  stack.setAttribute("data-active", String(active));
  // ... 그리고 각 시의 aria-hidden을 맞춰 같은 순간에 갱신
}
```

네 편의 시는 것의 아와레의 순서 — *도착 → 개화 → 낙화 → 기억* —
이며, 스크럽은 당신이 그 사이를 걷는 방식이다. 앞으로 스크럽하면 정원이
차오르고, 뒤로 스크럽하하면 비워지며, 시가 그에 맞춰 교차한다. 핀 된
무대는 당신이 어느 시에든 원하는 만큼 머무를 수 있게 하고, 개화는 그
아래에서 계속 도착한다.

## 모션 수학

두 숫자가 정원의 기질을 정한다.

- **속도 완화 1.8 s⁻¹.** 매 프레임마다, 꽃잎은 자기 속도와 장 사이의
  간극 중 `1 − e^(−dt·1.8)`를 건넌다 — 반감기 약 385ms. KEMURI의
  연기(2.4 s⁻¹, ~290ms)보다 무겁다. 꽃잎이 연기보다 항력이 크기
  때문이고; 연기가 오르던 자리를 정원이 흐르는 것이다. `dt`에서 계산되므로
  구조적으로 프레임률 독립적이다.
- **어택 0.06 / 릴리즈 0.02.** 포인터 에너지의 lerp, 60fps 기준 정규화.
  반감기 ≈ 들어올 때 12프레임, 나갈 때 34프레임. 정원이 손을 향해
  도는 것은 KEMURI의 연기와 비슷한 속도지만, 잊는 건 약간 빠르다 —
  꽃잎이 연기보다 가볍고, 바람은 곧 움직이기 때문이다.

나머지는 모두 두 이징을 따른다: `ease-bloom`
(`cubic-bezier(0.22,1,0.36,1)`)은 이동을 앞으로 몰아넣고 꼬리를
가라앉히며, 900–1100ms가 느림이 아니라 피어남으로 읽히게 한다;
`ease-ink`(`cubic-bezier(0.65,0,0.35,1)`)는 두 물리적 동작 — 로더의
밤 걷어냄과 버튼의 개화 채움 — 을 위한 대칭적이고 무게진 곡선이다.
앰비언트 사이클(수면의 미세 반짝 6.2초, 힌트의 떠다님 8.6초)은 서로,
그리고 미풍의 주기(~33초, ~15초)와도 서로 소여, 쉬지 않는 정원은 결코
눈에 띄게 루프하지 않는다.

## 성능 메모

- 개화를 위한 rAF 루프 하나, ~64fps로 조절(`FRAME_MS = 15.5`),
  `dt`는 48ms로 상한하여 백그라운드 탭이 돌아왔을 때의 발걸음이 없도록.
  루프는 IntersectionObserver(80px 여백) *와* `visibilitychange`로
  멈춘다 — 화면 밖이거나 탭이 숨겨진 프레임은 없다.
- DPR은 2로 상한; 꽃잎 수는 스테이지 면적에 비례(120–520). 꽃잎 하나는
  컬을 위한 8번의 값 노이즈 평가(ψ 샘플 4 × 2 옥타브)와 미리 그려둔
  스프라이트의 `drawImage` 한 번 — 입자마다의 `createRadialGradient`도,
  그림자도, 프레임마다의 경로 구축도 없다.
- 사전 이동(90 × 90ms 스텝)은 마운트 시 한 번, 동기적으로 돈다: 약 8초의
  시뮬레이션 시간을 한 프레임치 일로.
- 시 바인더는 별도의 깃털 같은 rAF(역시 15.5ms로 조절)로, 여섯 줄의
  수학과 변경마다 기껏 한 번의 DOM 속성 기록만 한다 — React를 한 번도
  다시 그리지 않는다.
- 모든 CSS 애니메이션은 `transform`, `opacity`, `filter`다. 리빌은 하나의
  관찰자 콜백에서 `class`와 `transitionDelay`를 기록하고; 시 교체는
  `data-active` 속성 하나를 기록한다. 스크롤에 대한 React 재렌더링은
  페이지 어디에도 없다.

## 접근성 메모

- **모션 저감:** 로더는 결코 마운트되지 않고(겹침으로 `display: none`),
  개화는 사전 이동 뒤 완성된 한 정지 화면을 그린다(정원이 한창 핀
  상태, 먹방울 하나가 떨어지는 중간에 멈춘 채, 꽃잎은 미풍이 잡은
  자리에 쉬고), 시 구간은 첫 시를 정적으로 보여주며, 미디어 쿼리가
  모든 트랜지션과 앰비언트 사이클을 평평하게 한다. 결과는 멈춰 비디오가
  아닌, 완성된 정원이다.
- **no-JS:** 모든 사전 리빌 상태는 마운트 시 더해지는 `.sakura-js`
  뒤에 숨겨진다; SSR 페이지는 곧 완성된 페이지다 — 첫 시가 보이고,
  워드마크가 자리하며, 캔버스가 JS 없이는 비어 있더라도 그 의미가
  캔버스의 `role="img"` 라벨로 전해진다.
- **의미론:** 모든 캔버스 무대는 한국어·영어 두 언어 설명을 단
  `role="img"`; 워드마크는 `aria-label`을 가진 `h1`; 세로 桜花는
  `aria-hidden`(장식); 시 스택은 활성 시만 읽히도록 `aria-hidden`을
  관리; 장식용 인장은 `aria-hidden`.
- **키보드·터치:** 두 상호작용 요소(다시 피우기 버튼, 맨 위 링크)는
  `:focus-visible`에 2px 분홍 링을 가진다. 정원은 터치에서도 스스로
  흐르고; pointer-down은 누구에게나 잉크를 떨어뜨리며; 어디에도 호버
  뒤에 숨은 것은 없다.
- **대비:** petal-white 17.2:1, bloom 12.6:1, blossom 7.8:1(본문도
  안전), gold 8.6:1, ink-soft 7.3:1 — 모두 먹밤 위. moss-ink(3.1:1)는
  큰 글자·장식 전용이며 결코 의미를 싣지 않는다. 꽃잎이 스쳐 지나갈
  최악의 경우에도 워드마크는 ≈ 9:1로 읽힌다.

## oneshot-sakura에 어떻게 답하는가

그 레퍼런스 사이트가 `ink-bloom` 패밀리를, 그리고 부분적으로는 이
갤러리 자체를 영감했다. 이 엔트리는 정직하게 표기된 답이다: 같은
보호받지 않는 전제(잉크가 떨어져 꽃으로 핀다)를 빌려온 코드나 자산 없이
처음부터 다시 쓰고, MIT 아래 전체 소스와 토큰, 그리고 이 정직한
프롬프트와 함께 내놓는다. 레퍼런스가 하나의 히어로를 보여준다면, 벚꽃은
페이지 전체를 — 히어로, 네 편의 스크럽 시, 열린 정원, 푸터 — 삼언어로
(한국어 메인, 일본어 장식, 영어 자막), 모션 저감에 안전하고, no-JS에서
견디며, 한 명령으로 설치되게 출하한다. 잉크에서 꽃으로의 전환은 캔
애니메이션이 아니라 실제 발산 없는 컬 노이즈 장(KEMURI가 연기에 쓰는
같은 엔진을 가라앉음으로 뒤집은 것) 위에 세워졌고; 읽을 때 꽃잎이
쌓이고 떠날 때 지워지는 스크롤 스크럽 시 구간은 레퍼런스가 갖지 못한
시그니처 모먼트다.

## 리믹스 아이디어

1. **가을.** 컬 장과 충격 순간의 개화 이벤트를 그대로 두되, 꽃잎
   스프라이트를 단풍잎(일곱 갈래 경로)으로 바꾸고, 팔레트를 분홍에서
   장작빛과 녹으로 옮기며, '방울'을 비로 만든다. 수면은 웅덩이가 되고,
   것의 아와레는 *이슬* — 가을의 이슬 — 이 된다.
2. **눈의 정원.** 개화를 뒤집는다: 입자가 (수면이 아니라) 꼭대기에서
   태어나, 영에 가까운 부력과 높은 항력으로 내려오며, 결코 피어나지
   않는다 — 그것들은 스테이지 아래에 *쌓여*, 스크롤 스크럽이 지우는
   정지한 설원을 이룬다. 시는 침묵이 된다.
3. **불꽃놀이 밤.** 먹방울을 불씨로, 꽃잏을 불똥으로 바꾼다; 개화는
   *폭발*(방사형, 고속, 짧은 수명, 중력이 그것들을 되돌려 보내는)이
   된다. 컬 장은 폭발마다 부력 펄스를 얻는다. 팔레트는 먹밤 위의
   따뜻한 금색 하나로 모인다 — 정원은 화로가 된다.
