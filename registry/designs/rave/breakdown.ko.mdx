# 레이브 — 제작기

## 훅: 파란 문 앞에 붙어 있는 전단

이태원의 폐인쇄공장, 새벽. 파란 문 옆 벽에 아직 붙어 있는 전단이 곧
이 페이지다. 레이브 2099는 원나잇 언더그라운드 전자음악 페스티벌이다.
룸 둘, 아티스트 열 팀, 밤 10시 문 열고 새벽 6시 불 끈다. 페이지는
음악을 한 번도 설명하지 않는다. 새벽 2시에 130 BPM이 어떤 건지 이미
아는 사람이 왔다고 가정하고, 남은 질문은 메인 룸이냐 지하냐 하나뿐이라는
태도다. 화면 전체가 검은 벽에 흰 블록을 콜라주하고 그 위에 전기파랑
스트로브 하나가 도는 구조 — 웹사이트가 아니라 전단이다.

이 디자인의 도박은 블런트와 같은데, 낮과 밤을 바꿔서 친다. 거친 것도
규칙이 될 때까지 반복하면 게으름이 아니라 공예로 읽힌다. 다만 블런트가
낮에 공예를 한다면(종이, 잉크, 핀 나간 리소, 던지는 스티커 작업대),
레이브는 밤에 한다(검은 바탕, 흰 블록, 스트로브 하나, 템포 위를
도는 라인업 티커 셋). 같은 교리, 하루의 반대편. 흑백 스크린샷이
증거다 — 블런트는 밝은 바탕에 어두운 글자, 레이브는 어두운 바탕에
밝은 글자. 둘을 헷갈릴 수 없다.

## 아트 딜렉션

팔레트는 칩 네 개고 그중 하나가 스트로브다. ground `#000000`이 밤이고,
block `#ffffff`가 글자를 얹는 모든 패널이고, ash `#8a8a8a`가 제목
아래에 앉는 보조 메타데이터고, 전기파랑 `#0066ff`가 단 하나의 액센트다.
이 파랑은 페이지에 딱 여섯 곳에만 등장한다 — 워드마크 밑판, 섹션
한글 부제, 강조 티어, 마퀴 B줄, 베뉴 맵의 입구, 푸터의 22:00 숫자 칩.
적기 때문에 스트로브가 된다. 어디든 있으면 브랜드 컬러지, 스트로브가
아니다.

정직성을 지키는 규칙은 대비 측정이다. 검은 바탕 위 전기파랑은 약
4.35:1이다. 큰 글자 기준 AA인 3:1은 넘지만, 본문 기준 4.5:1에는
미치지 못한다. 그래서 파랑은 디스플레이/큰 글자 용도로만 쓰고, 본문은
전부 흰색(검은 바탕 위 21:1)이다. 파랑 위에 올리는 흰 글자는 4.83:1에
도달해서, 파랑 표면(강조 티어, 마퀴 B줄)에 흰 글자를 얹는 건 문제없다.
ash가 본문 크기로 등장하는 유일한 곳(스케줄 미세 출력, 베뉴 원장 비고)도
4.6:1을 넘긴다.

서체 셋, 직업 셋, 한글이 먼저. 블랙 한 산스는 400 웨이트 하나뿐인데
덩어리로 읽힌다 — 구글 폰트에서 브루탈리스트 무게를 가진 한국어 서체에
가장 가깝다. 두 로마자 스택 모두 이 서체로 시작해서 마크업 없이 모든
한글 글리프가 여기에 도착한다. 아키보 블랙이 로마자 디스플레이를
맡아 두 문자가 같은 무게로 앉고, 스페이스 모노가 표를 쓰지 않고도
스케줄을 탭ular하게 만든다. 워드마크, 아티스트명, 원장까지 한국어
서체가 하나라는 게 — 기획자가 전단 전체를 같은 무거운 서체로 손수
조판했다는 설정의 증거다.

## 기법 1 — 템포 위를 도는 마퀴

라인업 티커 세 줄이 각기 다른 고정 속도, 각기 다른 방향으로 돈다.
A줄은 헤드라이너(빠르게, ~200 px/s, 왼쪽, 흰 바탕에 검은 아키보 블랙),
B줄은 오프너(중간, ~120 px/s, 오른쪽, 전기파랑 바탕, 히어로와 같은
스트로브), C줄은 장르(느리게, ~70 px/s, 왼쪽, 검은 바탕에 ash). 이게
블런트와의 결정적 차이다. 블런트의 두 줄은 스크롤 속도에 묶여 있다 —
걸어 지나가면서 읽는 인쇄소 슬로건. 레이브의 세 줄은 제 각각의
시계 위에서 세 가지 BPM으로 돈다. 나이트라이프는 스크롤이 아니라
템포 위에서 돌기 때문이다:

```ts
// LineupMarquee.tsx — 템포 셋, 방향 셋, rAF 루프 하나
const ROWS = [
  { id: "a", acts: HEADLINE, speed: 0.20, dir: -1 },  // 빠르게, 왼쪽
  { id: "b", acts: OPENER,   speed: 0.12, dir:  1 },  // 중간, 오른쪽 (스트로브)
  { id: "c", acts: GENRE,    speed: 0.07, dir: -1 },  // 느리게, 왼쪽
];
// ...
offs[i] = wrap(offs[i] + row.dir * row.speed * dt, widths[i]);
tracks[i].style.transform = `translate3d(${offs[i].toFixed(2)}px, 0, 0)`;
```

각 줄은 자기 그룹을 네 번 반복 렌더링해서, 오프셋이 그룹 하나의 실측
너비에서 순환하면 이어짐이 매끄럽다:

```ts
function wrap(v: number, w: number): number {
  const r = v % w;
  return r > 0 ? r - w : r;   // 오프셋을 (-w, 0] 구간에 둔다
}
```

배관이 정성스러운 부분이다. rAF 루프 하나가 세 줄을 모두 적분하고,
`ResizeObserver`가 뷰포트가 바뀌어도 각 그룹의 실측 너비를 갱신하며,
80px rootMargin을 건 `IntersectionObserver`가 밴드가 화면을 떠나는 순간
루프 전체를 멈춘다 — 가만히 있으면 프레임 0개. `dt`는 48ms로
클램프돼서 백그라운드 탭이 깨어나도 티커가 순간이동하지 않는다.
움직이는 줄은 `aria-hidden`이고, 그 앞에 시각적으로 숨긴 문단 하나에서
완전한 라인업(헤드라이너, 오프너, 장르와 역할 표기)을 정확히 한 번
전달한다. 모션 최소화에서는 훅이 일찍 반환하고 모든 트랙의
`transform`을 지워서, 세 줄이 정지한 읽기 쉬운 띠가 된다.

B줄은 워드마크의 스트로브와 같은 2.6초 루프로 숨쉰다 — 선택자 하나가
둘을 묶는다 — 그래서 액센트가 페이지 위에서 밑까지 같은 박자로
펄스를 친다. 그 공유 리듬 덕에 스트로브가 두 개의 관련 없는
애니메이션이 아니라 방의 조명으로 읽힌다.

## 기법 2 — 클립패스 리빌: 페이드가 아니라 컷

주요 블록마다 방향을 인지하는 clip-path 컷으로 닦인다. 섹션 헤더는
우하단 모서리에서, 스케줄+맵 패널은 위에서, 티켓 티어 세 개는 각기
다른 방향에서 — 왼쪽 티어는 왼쪽에서, 강조된 가운데는 위에서, 오른쪽
티어는 오른쪽에서. 이 와이프는 부드러운 페이드가 아니라 단단한
기하학적 컷이다:

```css
/* styles.css — 페이드의 브루탈리스트 버전 */
.rave-js.rave-root .rave-reveal {
  --rave-reveal-inset: inset(0 0 0 0);
  clip-path: var(--rave-reveal-inset);
  transition: clip-path 620ms steps(8, end);     /* 이징 아니라 스텝 */
}
.rave-js.rave-root .rave-reveal--l { --rave-reveal-inset: inset(0 100% 0 0); }
.rave-js.rave-root .rave-reveal--t { --rave-reveal-inset: inset(0 0 100% 0); }
.rave-js.rave-root .rave-reveal--br {
  --rave-reveal-inset: polygon(100% 100%, 100% 100%, 100% 100%, 100% 100%);
}
.rave-js.rave-root .rave-reveal.is-revealed { --rave-reveal-inset: inset(0 0 0 0); }
```

`--rave-reveal-inset` 커스텀 프로퍼티 하나가 두 도형을 모두 담는다 —
네 방향에는 `inset()`, 두 대각 모서리(좌상, 우하)에는 `polygon()` —
그래서 트랜지션 규칙을 공유한다. 핵심 선택은 `steps(8, end)`다.
클립이 연속이 아니라 여덟 번의 이산 점프로 나아가서, 와이프가
디졸브가 아니라 기계식 셔터로 읽힌다. 페이드는 브루탈리즘을 무르게
만들고, 컷은 그걸 지킨다.

리빌은 작은 `useReveal` 훅이 모는다. `-8% 0px -8% 0px` rootMargin과
0.12 threshold를 건 `IntersectionObserver`가 블록이 들어오면
`is-revealed`를 붙이고 관찰을 푼다 — 섹션이 스크롤로 다시 들어올
때마다 닦이는 게 아니라 딱 한 번 닦인다. 구조적 결정이 둘 있다.
첫째, 리빌 전 숨김 상태는 `.rave-js .rave-reveal` 뒤에 게이트돼 있어서
SSR/JS 없는 페이지는 모든 클립이 열린 채로 배송된다 — 자바스크립트가
실행되기 전에 전단은 완성돼 있다. 둘째, 모션 최소화에서는 훅이 일찍
반환하고 CSS 블록이 `clip-path: none`, `transition: none`으로
세팅해서, 블록이 그냥 — 조판된 채로 — 움직임 없이 나타난다.

## 기법 3 — CRT 주사선: 종이가 아니라 빛

블런트의 텍스처는 종이 위의 그레인이다 — 정적 `feTurbulence`를 종이에
곱한다. 레이브의 텍스처는 어두운 방 위의 빛이고, 전부 CSS로 지어진다.
SVG 필터도, 이미지도, 캔버스도 없다. 레이어 둘:

```css
/* styles.css — 주사선 격자 (히어로 전용, 장식) */
.rave-hero__scanlines {
  background-image: repeating-linear-gradient(
    0deg,
    rgba(255, 255, 255, 0.05) 0 1px,
    transparent 1px 3px
  );
}
.rave-hero--strobe .rave-hero__scanlines {
  opacity: 1;
  animation: rave-scanline-drift 8s linear infinite;  /* 사이클당 한 줄 */
}
@keyframes rave-scanline-drift {
  from { background-position: 0 0; }
  to   { background-position: 0 3px; }   /* 정확히 한 줄 피치 */
}
```

3px 피치의 1px 흰선 격자, 알파 5% — 히어로 위에 CRT 인광 마스크로
읽힐 만큼 빽하고, 흰-검 대비를 위협할 만큼 빽하지는 않다(흰색이
21:1에서 시작하고, 검은 바탕 위 5% 오버레이가 국소 배경을 무시할
수준으로만 낮춘다). 격자가 8초마다 정확히 한 줄 피치를 미끄러지기
때문에, 래스터가 스크롤이 아니라 미끄러진다 — 느리고 거의 임계점
아래의 움직임. 읽히는 섹션(스케줄, 원장, 푸터)은 깨끗하게 두려고
히어로에만 건다.

두 번째 레이어는 스트로브 자체 — 워드마크의 전기파랑 밑판이 2.6초
`ease-in-out`으로 opacity 1 → 0.55를 숨쉰다. 이 판은
`content: attr(data-text) / ""`를 쓰는 CSS 가상 요소다(대체 텍스트
문법 덕에 스크린 리더가 RAVE를 두 번 읽지 않는다). 흰 잉크 층 아래에
오프셋하고 `mix-blend-mode: screen`으로 검은 바탕을 밝혀서, 파란
조명이 무대를 비추는 것처럼 만든다:

```css
.rave-word::before {
  content: attr(data-text) / "";
  position: absolute;
  color: var(--rave-strobe);
  transform: translate(0.04em, 0.05em);
  mix-blend-mode: screen;
}
.rave-js.rave-root .rave-hero--strobe .rave-word:not(.rave-word--deck)::before {
  animation: rave-strobe 2.6s ease-in-out infinite;
}
```

두 레이어 모두 이중 게이트다. 루트의 `.rave-js`(그래야 SSR 페이지가
스트로브를 켠 채로 얼어 있는 완성 전단이 된다)와 헤더의
`.rave-hero--strobe`가 둘 다 필요하고, `.rave-hero--strobe`는 Hero
컴포넌트가 `usePrefersReducedMotion`이 참을 반환하면 끈다.
모션에 민감한 독자는 깨끗한 검은 바탕 위의 정지 워드마크를 받는다 —
불은 켜져 있고, 스트로브는 멈춰 있다.

## 모션 수학

- **마퀴 템포 셋: 0.20 / 0.12 / 0.07 px/ms.** 헤드라이너가 장르 리스트보다
  대략 3배 빠르게 뷰포트를 가로질러서, 눈이 헤드라이너를 전경으로,
  장르를 앰비언트 질감으로 읽는다. 오프너 줄은 그 사이, 파랑 위에서
  스트로브를 친다.
- **스트로브 2.6초 ease-in-out, 1 → 0.55.** 45% 깊이에 2.6초 주기면
  광과민성 발작 임계 3 Hz를 아주 넉넉하게 아래로 지난다(약
  0.38 사이클/초로 완료). 워드마크 판과 마퀴 B줄이 루프를 공유해서
  액센트가 위상을 맞춘다.
- **리빌 620ms `steps(8, end)`.** 약 77ms짜리 점프 여덟 번 — 셔터처럼
  느껴질 만큼 빠르고, 방향을 읽을 만큼 느리다.
- **프레스 0ms in / 110ms linear out.** 블런트와 같은 안티-이징 교리,
  더 단단한 8px 오프셋과 살짝 더 긴 복귀 — 인쇄소보다 나이트라이프가
  더 세게 때린다.
- **`dt`는 어디서나 48ms로 클램프**, 백그라운드 탭이 깨어나도 티커가
  순간이동하거나 클립이 튀지 않는다.

## 성능 노트

- rAF 루프는 하나(세 줄짜리 마퀴)고 `IntersectionObserver`로 밴드가
  화면 밖이면 스스로 멈춘다. 클립패스 리빌과 스트로브는 CSS 구동이라
  프레임이 필요 없다.
- 움직이는 건 전부 `transform`, `opacity`, `clip-path`,
  `background-position`이고 레이아웃 속성은 없다. 주사선 격자와
  스트로브는 GPU에 친화적이다.
- 마퀴는 매 프레임 각 트랙에 `style.transform`을 직접 쓴다 — 핫 패스에
  React 상태가 없고, 밤새 스크롤해도 리렌더는 0회다.
- 캔버스 없음, 이미지 없음, 의존성 없음. 가장 무거운 에셋이 구글 폰트
  세 종이다. `media.source = "code"`, 예산 0.

## 접근성 노트

- **모션 최소화:** `usePrefersReducedMotion`(`matchMedia` 위의
  `useSyncExternalStore`)이 마퀴 루프를 멈추고(모든 트랙의 transform을
  지운다), CSS 블록이 주사선 오버레이를 `opacity: 0`으로 하고, 스트로브와
  리빌 트랜지션을 죽이고, 모든 클립을 연다. 페이지가 잃는 건 스트로브와
  와이프뿐이고, 전단 전체는 남는다.
- **No-JS:** 스트로브, 주사선 드리프트, 리빌 전 숨김 상태는 전부
  `.rave-js` 뒤에 게이트된다. SSR 마크업이 곧 완성된 페이지 — 파란
  판이 켜진 채로 얼어 있는, 완전히 읽히는 정지 전단이다.
- **키보드:** 룸 토글은 진짜 `role="tablist"`에 두 개의 `role="tab"`
  버튼이고, CTA는 링크, 포커스는 3px 스트로브파랑 링(검은 바탕과
  흰 푸터 모두에서 보인다).
- **스트로브 안전:** 워드마크 펄스는 초당 0.4 사이클 미만으로 완료돼서
  광과민성 임계 3 Hz를 한참 아래로 지나고, 모션 최소화에서는 완전히
  제거된다. 주사선 드리프트는 더 느리다(8초에 한 줄)이고 히어로 전용이다.
- **대비:** 흰/검 21:1, 흰/파랑 4.83:1, ash/검 4.6:1 — 기능적 본문
  조합은 전부 AA를 넘긴다. 검은 바탕 위 전기파랑(4.35:1)은 AA 큰 글자
  기준(3:1)이 적용되는 디스플레이/큰 글자 크기에서만 존재한다.
- **겹말 없는 스트로브:** 파랑 밑판은 `content: attr(data-text) / ""`를
  쓰는 CSS 가상 요소다 — 대체 텍스트 문법 덕에 스크린 리더가 RAVE를
  두 번 읽지 않는다.

## 리믹스 아이디어

1. **종일 라디오 방송국.** 세-템포 마퀴는 그대로 두고 라인업을 심야
   플레이리스트로 바꾼다(A줄은 현재 곡, B줄은 신청자, C줄은 연대)하고,
   티켓 블록은 후원 모금이 된다. 스트로브는 VU 미터가 된다.
2. **격투기 매치 홍보.** 같은 검/흰/파랑 시스템에서 스케줄은 카드
   (메인 이벤트/언더카드)가 되고, 베뉴 맵은 링+석이 되고, 클립패스
   리빌은 라운드 카드처럼 닦인다.
3. **24시간 해커톤.** 문-여는-22시를 카운트다운이 대신하고, 세 티커는
   팀명/트랙/스폰서를 세 속도로 돌리고, 스트로브는 마지막 한 시간의
   돌입을 표시한다.
